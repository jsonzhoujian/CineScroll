# 可信来源、执行关闭与共同事务适配契约

日期：2026-10-07。用户确认范围：契约、实施计划与未来验收；不增加运行时类型、迁移、真实来源接线或收费。继承[ADR0004](../adr/0004-evidence-source-seal.md)、[封存设计](EVIDENCE_SOURCE_SEAL.md)、[原子发布](EVIDENCE_ATOMIC_PUBLICATION.md)、[结算判据](SETTLEMENT_EVIDENCE.md)。以下接口为设计语义，不是现有可调用API。

## 1. 已有资料与缺口

现有ModelTask（packages/script/src/model-tasks.ts）保存工作室/项目/章节、原文及上游版本、模型快照、revision、状态、单个candidateVersionId和租约。它没有固定平台报价/预留/单元清单、独立发送记录、执行关闭证明、全部原始结果登记或共同来源头锁。候选保存与任务终态更新仍非共同事务；[恢复规则](MODEL_TASK_RECOVERY.md)允许租约过期后模型继续返回。

现有内存来源夹具只证明登记顺序和规则，不证明业务来源。不得把task.state、extractionStatus、leaseExpiresAt、客户端complete或sourceSealId字符串升级为可信执行结论；没有资料时不能创建默认完整空集合。

## 2. 可信来源包

所有对象必须携带同一固定binding：workspaceId/taskId/unitId/projectId/chapterId/sourceVersionId/upstreamVersionIds；上游数组顺序固定。每份来源有不可变recordId/version、规范化payloadFingerprint、来源生产服务及规则版本、记录时间和真实业务行关联。关联必须由受控服务器读取/核验，不能只存调用者自报指纹。引用不能被当前活动版本替换。

| 对象 | 必须保存并核验的资料 |
| --- | --- |
| 固定任务/单元 | 任务修订引用、明确生成范围、固定binding；计费单元与任务登记一致 |
| 固定计费快照 | 同binding、responsibility(platform/byok)、quoteId/priceVersion、reserved、报价规则引用；安全整数且BYOK预留0，平台预留为正 |
| 执行资料 | 唯一executionId、固定任务/单元、发送尝试/发送栅栏引用、已知发送边界、结果状态及关闭证明引用；不把任务修订作为执行ID |
| 原始结果登记 | 全部原始候选的ID/version/指纹、executionId、业务持久化位置、原始生成范围；包括重复、矛盾、未决结果，不只读取已选candidateVersionId |
| 校验 | 明确结果ID/version/指纹、固定ruleVersion、passed/failed及受控校验记录；人工接受不代替校验，局部结果只计已匹配单元 |
| 计价 | 匹配结果ID/version、固定quoteId/priceVersion、受控报价规则来源、amount；平台额度安全整数，BYOK为0，不直接采用usage或客户端金额 |
| 集合头/封存 | generation、完整版本成员列表及计数、未决/冲突标记、sealKind、封存规则版本/服务/时间、清单指纹；不存在或超限均拒绝 |

封存中保留全部历史来源版本，同时明确用于结论的执行/校验/计价版本引用。生产版本先后必须有受控revision/前序关系，不按字符串大小或到达顺序选“最新”。同身份同版本异内容构成冲突；执行结论变化缺少合法前序证明时不得final。manifest字段顺序/数组顺序规则及指纹测试向量在实现前冻结。

来源资料最小化：不复制小说正文、完整提示词、Key、供应商私密响应或错误；业务行关联指向受保护资料。日志只保留净化状态与必要定位信息。来源写权限、封存权限、发布权限分开，由固定服务器身份授权；工作室上下文不可由浏览器选择。

## 3. 执行关闭证明

关闭证明至少绑定executionId、固定binding、发送栅栏版本、关闭前序、关闭原因、可信执行服务/规则/时间。它证明受控发送与正常结果入集合路径已关闭，而非证明供应商以后绝不会回复。正常来源写入必须检查同一栅栏/集合头；晚到事实仍能进入独立隔离，不能静默丢弃。

| 情况 | 必需证据与允许结论 |
| --- | --- |
| 明确未发送 | 所有发送者受同一持久化栅栏约束，未获发送资格且可发送路径已关闭；仅queued/paused不够。满足既有not_sent判据可final失败 |
| 可能已发送，超时/崩溃/取消/租约失效 | 无法排除在途请求；保持unknown观察，不以本地Abort、HTTP失败或未查到候选证明失败，也不重投模型 |
| 明确完成，唯一原始结果 | 结果已持久化且关联完整，正常发送/入集合路径已关闭；校验通过且计价齐全才final成功，校验失败按既有判据final失败，无计价消费 |
| 明确无可用结果的非法响应 | 可信响应处理事实、关闭栅栏及完整无结果集合齐备，符合invalid_response判据可final失败；不能把网络故障伪装为非法响应 |
| 多原始结果/矛盾结论/未决来源 | 清单必须保留，拒绝final，不任意选一条；unknown观察也必须符合既有投影判据，不能把有结果冲突伪装成空结果unknown |

关闭写入与受控来源登记必须锁同一集合头并核验栅栏代，不能先关任务再让旧Writer照常插候选。observation后新资料进入新generation，旧清单不变；final后正常来源不能重开，迟到/矛盾事实进入独立持久化隔离。隔离保存失败必须显式返回可重试的保存失败并由采集方保留事实；内存夹具的保存不满足此要求。

关闭证明不能自动抹去already-sent未知执行。unknown→确定结论需同executionId的新可信资料及新发布请求/前序关联，不能创建新执行ID掩盖旧请求或自动补扣。

## 4. 共同事务适配接口

```text
固定身份授权 → 规范化命令 → 请求身份锁/历史回执
                                      ↓ 新请求
同一连接事务：来源头锁 → 栅栏/封存/全成员重验 → 前序关联重验
             → 最终material判据 → 请求/资料/审计/回执 → COMMIT
```

建议publishFromSeal(command)为唯一提交边界，服务器装配仓储内部管理连接与事务，调用方不获得transaction client，不接受外部material/prepare草稿或任意Pool作为提交权威。命令包含protocolVersion、workspaceId、requestId、operation、固定来源引用、expectedSealId/generation/manifestFingerprint及predecessorId；serviceId来自固定装配。前置读取仅用于展示，最终资料在事务内从可信来源构造。

新请求指纹必须包含期望封存身份/代/指纹，改变任何一项不能绕过同请求冲突。现有evidence-publication-v1没有这些字段：用户已确认新边界定义独立v2，不改写v1函数和历史指纹，见[ADR0005](../adr/0005-evidence-publication-v2.md)及[v2规范](EVIDENCE_PUBLICATION_V2.md)。历史v1记录仍按原规则读取/重放，不自动变为生产published；跨版本共用(workspaceId,requestId)，另一版本占用即冲突，不自动升级或降级。共同登记和历史迁移尚未实现。

逻辑读取接口为lookupPublished(workspaceId,requestIdentity)及readPublishedEvidence(workspaceId,evidenceId)，每次先授权；恢复查询只返回完整已提交关联。相同命令重放已有回执不依赖当前来源头，历史读仍核验其不可变清单；不同指纹冲突。新请求要求期望seal仍是当前头且版本成员/栅栏证明完整。unknown前序补证核验同binding/快照/executionId；不自动裁决账本终态冲突。

统一锁序为请求身份→稳定顺序的来源头→不可变前序读取。所有来源/关闭/封存Writer遵守同头屏障；真实写路径及数据库权限未封闭前生产发布默认禁用。请求锁具体实现、SQL约束、启动预检、限额和时限另行批准，不能只靠隔离级别或点时requireCurrentSeal防止新增结果。

四项保存失败回滚；COMMIT响应丢失时返回净化待核对状态，原requestId查询/重放，未读到不能断言未提交或換ID。锁内不访问模型/网络/Key，分别设置锁等待、语句及整体截止；取消请求不证明回滚。服务关闭后不暴露半提交资料。低层append不参与拼接事务；来源封存本身可在之前提交，但最终发布重验封存与头。

生产读取须核验同工作室请求/资料/审计/回执/封存完整关联、最终ID/全部指纹和规则版本后投影九字段；不要求历史seal仍为当前头。裸资料、缺审计/回执或夹具封存不能放行。不得在formatVersion=1中塞未知字段，审计和来源关联独立保存。

## 5. 取舍、实施边界与运营要求

同数据库复用ADR0004，减少外部证明协议但要求升级所有发送/结果/校验/计价Writer。备选的点时草稿串接append已拒绝；外部签名封存属于未来独立方案，不在缺来源时回退。本设计只保护证据发布，不提供任务冻结/Outbox/账本共同事务，published不等于已消费积分。

容量需同时限制成员数、单清单字节、每单元历史和隔离增长；不能复制内存64/256上限作为生产容量结论。超限拒绝、不截断，采集事实可靠保存另行实现。总留存/删除权限/历史迁移尚未批准，不得直接复用项目删除策略。生产启用前须证明：来源认证和真实记录关联、所有Writer升级、权限/RLS/启动预检、并发实库回归、异常事实保留/查询与人工裁决职责。没有全部满足不得开启收费。
