# 同数据库来源封存与发布事务设计

日期：2026-10-07。用户选择A：同数据库封存。范围仅设计、接口语义与未来验收；不实现迁移、真实来源、发布事务或扣费。

依据：[原子发布契约](EVIDENCE_ATOMIC_PUBLICATION.md)、[任务恢复](MODEL_TASK_RECOVERY.md)、[ADR-0004](../adr/0004-evidence-source-seal.md)。现有sourceSealId字符串和内存回执不构成本设计的屏障实现。

## 1. 架构与信任根

```text
可信来源写入 → 单元来源集合（锁定头、追加版本）→ 不可变封存清单
                                                   ↓
授权发布请求 → 同数据库事务：锁头/核验清单 → 请求+资料+审计+回执
                                                   ↓
                         授权的已发布证据读取（关联门禁）
```

首版同一PostgreSQL数据库内，来源封存与发布共享事务连接。任务执行/结果/校验/计价生产者必须进入受控来源写路径，绑定真实业务记录；不能仅复制自报JSON并称可信。现有任务仓储没有此集合屏障，现有Writer也未接入，本设计不能直接以当前任务状态收费。

来源登记、封存、发布为不同服务权限，成员审核与账本权限不推导这些能力；数据库角色仅获相应写入/读取权限，forced RLS且工作室上下文由服务器控制。业务owner、来源写服务认证、角色/启动预检及真实提供者适配需后续实现，不把同数据库等同于真实性证明。

## 2. 概念结构（非迁移）

| 对象 | 固定资料与不变量 |
| --- | --- |
| 来源集合头 | workspace/task/unit、当前generation、固定计费快照、当前封存ID/结论类型；所有结果登记和头推进必须锁同一行 |
| 来源版本记录 | 来源类型、不可变ID/version、payloadFingerprint、真实业务记录关联、生产服务/时间、generation；只追加 |
| 封存清单 | sealId、workspace/task/unit、generation、固定绑定/快照、全部原始结果ID/version与计数、执行/校验/计价引用、规范化清单指纹、sealKind、服务/时间；不可变 |
| 发布关联 | 请求与最终证据/审计/回执、sealId/generation/清单指纹；四项共同提交，引用同工作室封存 |

来源集合必须预先存在，不能用“查不到结果”创建默认完整空清单。清单不能只包含调用者指定结果，必须列举集合内所有原始候选与未决/冲突信息；普通查询没读到不等于没有。字段上限、结果数上限、总容量、索引和保留期实施前明确，超限拒绝，不截断清单。

## 3. 封存规则与迟到结果

封存事务锁来源集合头，核验固定任务/单元/原文/上游/责任/报价，读取该generation的全部来源资料并检查唯一性，追加清单并关联头。同版本/内容幂等，异内容冲突；清单字段/指纹由服务器计算，不接受客户端complete=true证明。

sealKind区分：

- observation：只记录已经可信证明的未知执行及当时完整观察范围，不宣称远端执行关闭或永不出现结果。允许以后追加新的generation；旧清单仍是历史未知依据。
- final：执行/发送路径已受控关闭且结论可确定，所需结果/校验/计价齐备；明确失败的“未发送”也须关闭可发送路径。结果唯一性或来源冲突未解时不得final。

迟到结果发生在observation后：锁同一头，将新资料追加到新generation，产生新清单；发布用新requestId和新证据，并关联旧证据。不得把新结果插入旧清单，也不得沿用旧sealId冒称仍完整。旧unknown已发布不因此被覆盖；旧请求重放返回历史回执。

迟到/冲突结果发生在final后：正常来源登记路径不得把它当作可消费结果加入既有集合或覆盖final。可信采集可以保存到独立异常隔离记录（保留必要引用/指纹，不能丢弃事实），交给待设计的有权限对账流程；不自动改账本或重开已关闭单元。隔离/裁决接口本轮未实现。

旧observation清单在新generation出现后不能用于新的发布请求，因为当前头已变化；既存发布回执重放不重新要求头仍是旧generation。这样既保留历史未知证据，又不把后来出现的结果隐藏为“仍未知”。

## 4. 事务接口（建议形状，尚未实现）

发布事务仓储应在内部管理连接、BEGIN/COMMIT/ROLLBACK，不能让调用方把任意Pool混成同一事务。核心命令只接请求身份、来源引用、期望sealId/generation/清单指纹及补证前序，不接受外部material或点时草稿作为提交权威。

逻辑接口：publishFromSeal(command)→已提交回执；lookupPublished(workspace,requestId)→回执；readPublishedEvidence(workspace,evidenceId)→已发布关联及严格投影。实际TypeScript类型及SQL在后续TDD前确认。四项原子提交接口需与封存读取/校验共享连接，不通过现有独立append调用拼接。

新请求事务顺序：

1. 服务先验证固定身份、工作室及publish/supplement权限，规范化请求指纹。
2. 在同工作室请求身份锁/唯一键保护下检查既存回执；同指纹返回原回执，异内容冲突。未提交映射不能对外可见。
3. 锁来源集合头，要求expected generation/sealId与当前头一致，核验不可变清单指纹、全部版本引用及未决结果；不按最新头静默换引用。
4. 读取最终事务中的前序发布关联并校验同工作室/绑定/快照/执行ID；前序资料不可变，不自动裁决结论冲突。
5. 从可信封存资料构造最终协议ID的material，重验判据，生成完整来源审计，四项保存并提交。提交成功才返回回执。

建议统一锁序：请求身份→来源集合头（多个时按稳定workspace/task/unit排序）→前序不可变记录读取；前序本身不要求改写锁。请求身份锁的具体实现（键行/事务锁）及有界锁等待后续决定，不允许因死锁或超时换requestId。

保护必须覆盖所有来源写入者：结果插入与generation推进同事务，先锁头；封存清单只追加且引用同代资料。应由数据库约束/受控写入口封闭绕过路径。只锁发布线程，而允许其他Writer直接插入候选，不能防止幻读或第二个结果。数据库与业务写路径全部接齐前，生产发布默认禁用。

未知回执lookup、事务响应丢失及并发重放沿用原子发布契约；来源变化拒绝新发布，不伪造failed/unknown。READ COMMITTED可在共同头锁及所有Writer遵守屏障时使用，但隔离级别本身不是屏障；实际实现须实库验证并发插入等待及锁释放。

## 5. 非功能与读取门禁

事务锁内只读本库受控来源与写发布资料，不调用模型/外部网络或解密Key。区分语句超时、锁等待上限和整体截止，具体值实施前确认；取消/断网不证明回滚，仍用原请求查询。来源清单和审计最小化，不复制小说/提示词/Key/厂商私密错误；ID/版本/指纹不足以证明真实性时拒绝而非填补。

生产读取仅放行请求/资料/审计/回执/封存关联完整且同工作室的记录，重验最终ID、资料与清单指纹，再输出九字段。不可只检查evidence_material存在。当前低层资料与旧夹具默认不成为published；迁移/导入历史证据必须另行批准，不能回填虚构审计。读取历史已发布证据不要求当前头仍为旧generation，但必须能读取其不可变清单与原发布关联。

取舍：同数据库让屏障与四项提交可用事务保护，减少外部签名/证明协议复杂度；代价是来源生产者与发布库耦合，需要协调所有Writer升级、容量和迁移。它不解决厂商响应真伪或质量规则批准，也不提供Outbox/计费任务共同事务。外部来源路线作为未来独立方案，不能在A缺资料时自动降级。
