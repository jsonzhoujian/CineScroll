# 工作室任务运行上限

script/0009新增workspace_task_limits，数据库管理员配置max_queued/max_executing（非负整数，0关闭对应新准入）。应用角色只读且工作室RLS隔离，不能客户端指定或提高上限。配置缺失关闭准入；生产未装配，旧任务不自动清理或取消。

所有工作室model_tasks共同计数，不按项目、章节或阶段分别放大额度。队列仅queued；执行占用为running（包括过期/无租约旧任务）及paused/EXECUTION_UNCERTAIN。发现持久结果并修复为succeeded后才释放未知占位；其他已落定failed/普通paused/succeeded不占执行。降低配置不会取消已有任务，可能暂时超过新上限，但禁止进一步准入。

仓储insert与queued→running的事务内触发器，锁工作室限额行后按最新提交状态统计并判断。不同任务/多连接共享同一准入锁。模型调用在事务提交后，不持数据库锁等待供应商。Postgres仓储显式READ COMMITTED；触发器对其他隔离级别拒绝准入，避免旧快照统计。退出/对账不要求配置存在，配置撤销不阻止结果落定。

错误：TASK_QUEUE_FULL/429（创建及重提）、TASK_EXECUTION_FULL（内部调度limited，任务仍queued）、TASK_LIMITS_UNAVAILABLE/503（缺配置或不满足准入要求）。没有基于时间的Retry-After，不自动重发模型；调用方按既有游标周期再检查未运行任务。当前不包含常驻调度器。

内存夹具构造时注入可信限额函数，缺失同样关闭；无成员setter。实库触发器需由受信任、具RLS绕过权限的迁移角色拥有，PUBLIC/应用不能直接执行或替换。配置维护审计、额度管理UI、订阅积分/账单、超级管理员DDL约束及生产部署另行实现。数据库连接/模型请求超时不证明远端已终止，此规则不替代取消与未知执行治理。

验证：共享契约的队列竞争、独立任务抢占竞争，过期/未知继续占位与恢复释放，配置缺失、应用配置写拒绝；HTTP超限429和调度保持排队/不增加模型调用。只应用临时库，不升级业务数据库。
