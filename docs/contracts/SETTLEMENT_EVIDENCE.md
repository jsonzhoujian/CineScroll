# 可信结算证据契约与验收用例

日期：2026-10-07。范围：方案A，仅文档与未来验收要求，不交付证据适配器、迁移、报价或真实扣费。

依据：[积分结算契约](AI_CREDIT_SETTLEMENT.md)、[任务恢复规则](MODEL_TASK_RECOVERY.md)，以及packages/billing/src/index.ts与packages/script/src/model-tasks.ts现有接口。

## 1. 信任边界

模型回答、供应商usage、任务state=succeeded、用户点击确认都不是独立的结算凭证。证据服务必须从可信持久化任务、固定计费快照、结果记录和校验结论中建立关联，不能接受客户端提交的金额或成功范围。

证据产生与账本应用分开：证据服务判定并保存不可变证据；SettlementEvidenceReader按工作室和证据ID读取已验证资料；账本再次核验任务/单元/原文版本、金额和幂等性。账本字段校验不证明外部结果真实。

当前任务仅有BYOK路线，ModelTask没有完整平台计费快照、报价和可信单元清单。不得直接把现有任务状态转换为平台扣费。

## 2. 上游证据资料（未来接口，不是已有类型）

| 资料 | 必须证明的关系 |
| --- | --- |
| 固定计费快照 | workspaceId/taskId/projectId/chapterId、sourceVersionId、固定上游版本、platform/byok、quoteId/priceVersion、单元ID及预留上限 |
| 执行记录 | 同任务/单元与唯一执行关联ID，可信发送边界、明确完成/未执行/未知；状态来源不能是浏览器或模型自报 |
| 原始结果版本 | 唯一任务关联，匹配工作室/项目/章节/原文版本；原始版本不是当前活动头或审核派生版本 |
| 校验结论 | 版本化规则、范围覆盖、结构及引用检查，通过/明确失败/不确定；校验服务身份与时间 |
| 计价结论 | 固定quoteId/priceVersion及已批准规则，安全整数积分、计算输入摘要和来源引用，不用供应商成本替代用户积分 |

若来源不唯一、版本错配、单元未规划或价格规则缺失，不生成可消费证据。既有冻结保持，交给异常对账；资料存储不可用属于读取失败，不能伪造“失败证据”释放。

## 3. 判定与账本投影

| 判定 | 必要依据 | 账本投影 |
| --- | --- | --- |
| succeeded | 原始结果已持久化且可交付，任务/版本/单元绑定唯一，既定校验通过，可信计价已确定 | amount为非负安全整数，resultVersionId非空 |
| failed：确定未执行 | 可信执行边界证明未发送且不能再执行；须先关闭/隔离可执行路径，避免释放后旧Worker继续发送 | amount/resultVersionId均null，释放原预留 |
| failed：明确业务失败 | 可信记录证明本单元执行结束且产物明确不符合既定规则，无未决成功结果 | amount/resultVersionId均null，供应商成本另记 |
| unknown | 已发送但超时、租约过期、无候选、写入不确定、取消在途或记录冲突无法判定 | amount/resultVersionId均null，保持冻结待对账 |

排队且仍可执行时不能当作failed或仅凭等待时长生成unknown；保持原排队/预留状态。任务paused/failed字样不能替代执行边界证据。task=succeeded且extractionStatus=failed也不证明可计费成功。

单元成功判定的具体质量规则与计价规则仍待确认，本契约不擅定“结构合法就收费”。用户拒绝合格候选不自动撤销成功证据。部分成功仅依据提交前固定的单元清单分别判定；模型临时新增条目/集数不能扩大收费范围。

超过预留的可信金额保留为异常证据，由既有账本返回QUOTE_EXCEEDED并保持冻结；不截断金额、不补扣、不擅定谁承担差额。BYOK保持原责任，不产生平台积分流水；供应商收费与其用户结算分离。

## 4. 保存记录与现有读取接口

未来不可变EvidenceRecord至少保存：证据ID、版本化记录格式、上述绑定标识、outcome、校验规则版本、执行/结果/计价来源引用、验证服务标识、验证时间和规范化内容指纹。成功金额来源可审计。来源引用所指记录同样必须不可变或带版本/指纹。

现有SettlementEvidenceReader.read(actor,evidenceId)返回的严格投影只有：id、workspaceId、taskId、unitId、sourceVersionId、outcome、amount、resultVersionId、ruleVersion。不要将新增元数据直接塞进该对象；现有账本会拒绝额外字段。适配器先核验完整记录，再投影；ruleVersion引用可追溯的判定规则版本，不替代记录格式或priceVersion。

缺失、越工作室、未验证、来源冲突或依赖异常不得返回可用投影。对账层区分未找到、暂不可读、冲突，使用净化原因；现有账本统一INVALID_EVIDENCE，不改变余额。未知证据是已验证“无法判定”的记录，不是任何读取异常的别名。

同证据ID+同内容保存幂等；同ID不同内容拒绝。新证据只能追加，不覆盖unknown或终态证据。unknown后补齐结果以新证据ID和新eventId推进；证据关联前序记录。相同eventId重放必须使用原证据，不拿后来成功证据替换原unknown事件。

已释放/已消费单元收到矛盾结论时保留历史、异常对账，不自动重开。应用失败或结果未知保留原eventId查询/重放，不重新生成模型、不新建事件猜测是否记账。固定事件身份由可信服务持久化分配，不能由每次调用随机生成。

## 5. 一致性与恢复

证据保存成功不等于账本已结算；需要持久化待应用关联和恢复扫描。证据与结算若不在共同事务，恢复按工作室+任务+单元+证据/事件身份读取，不能只扫描最新活动候选。

对账只能读取和核验既有资料，不调用模型或解密Key。并发应用由现有账本CAS/幂等约束收敛；证据唯一性及任务结果绑定仍需未来证据仓储保证。当前独立账本没有任务/冻结/Outbox共同事务，不能宣称端到端恰好一次。

项目删除、成员退出和当前订阅变化不能抹除冻结任务的绑定事实；计费保留期与可交付内容删除策略另行批准。若结果已删除且没有可信历史交付证明，不能凭结果ID猜测成功。

证据不包含小说、提示词、API Key、原始厂商响应或私密错误。仅保留必要标识、净化结论和审计引用；留存期限、对账权限及告警渠道尚未定。

## 6. 未来验收用例（本轮未运行）

固定示例：授予100、单元预留60、可信成功金额50。数字不是定价。

| 编号 | 输入/故障 | 预期 |
| --- | --- | --- |
| E01 | 同任务原始结果唯一、版本/单元匹配、规则通过、可信报价确定50 | 成功投影；应用后可用50/冻结0/消耗50 |
| E02 | 仅task=succeeded；无原始结果或extractionStatus=failed | 不据此生成成功证据；无暗扣 |
| E03 | 工作室/任务/原文/上游/单元任一错配，或多个原始结果 | 拒绝可用投影，冻结保留，净化错误 |
| E04 | 审核派生版本成为当前头，原始结果仍可定位 | 使用任务绑定原始版本，不按当前头结算 |
| E05 | 调用发送后超时、无候选或租约过期 | unknown，预留60保持；模型调用次数不增加 |
| E06 | queued取消，仅UI称未执行；可信发送路径尚未关闭 | 不释放；不能将本地取消当作远端停止 |
| E07 | 可信路径关闭且确定未发送；或明确非法响应终态 | failed投影，原预留全部释放，成本另记 |
| E08 | 报价版本缺失、金额来源客户端或供应商费用 | 不生成可消费证据，不使用当前价格替代 |
| E09 | 已确定金额70但只预留60 | QUOTE_EXCEEDED，冻结60保持，不截断/补扣 |
| E10 | 同ID同内容重复保存；同ID不同内容 | 前者同记录，后者冲突，不覆盖 |
| E11 | 同事件重放；新事件重复应用同证据 | 前者同回执且不双扣，后者拒绝 |
| E12 | unknown证据已应用，后来出现匹配成功结果 | 新证据/事件推进一次，旧unknown不可变 |
| E13 | 已释放后迟到成功或已消费后冲突失败 | 拒绝终态改写，保留流水并异常对账 |
| E14 | 证据已存、结算响应丢失/进程崩溃 | 以原事件读取/重放，最终只结算一次，不调用模型 |
| E15 | 模型新增未规划scope/集数，或部分结果有未决范围 | 不扩充收费单元；已规划单元分别判定 |
| E16 | BYOK更换Key或订阅变化后收到结果 | 原责任不变，平台积分不变 |
| E17 | 证据读取暂不可用或权限不匹配 | 不伪造failed/unknown，账本不变，错误不泄密 |
| E18 | 项目删除后只剩结果ID且无交付证明 | 不猜测成功；保留必要对账关联，留存另行确定 |

## 7. 下一实施边界

建议先实现只读证据验证/投影适配器，公开测试边界为“可信资料读取 → 验证 → 严格投影”，暂不挂现有任务或生产扣费。可先用授权夹具验证绑定/去重/不确定分支；夹具不等于生产证据。

接真实任务前必须批准：可信单元规划、报价和成功质量规则；明确执行边界的持久化与关闭机制；证据仓储及来源唯一性；事件身份、恢复扫描、权限和留存。未批准时默认拒绝可消费证据，不能自行填入价格。
