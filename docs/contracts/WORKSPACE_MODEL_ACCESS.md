# 工作室 BYOK 权限与人工订阅

本阶段提供只读权威适配器 `PostgresWorkspaceModelAccess`，供模型设置服务注入。生产 API 尚未挂载；不包含支付、管理后台或自动开通订阅。

## 权限规则

- 成员记录独立于项目角色；不得从项目负责人推断工作室负责人。
- 工作室最多一名有效负责人，可包含编辑、审核人。无记录或停用成员返回无权限。
- 高级订阅必须启用，且数据库当前时间在 `[starts_at, expires_at)` 内。普通套餐、缺失、未来生效或已过期均不能使用 BYOK。
- 有效高级成员可读取脱敏配置；只有负责人能修改和测试共享 Key。每次服务操作重新查询，不缓存权限。
- 数据库故障返回 `STORAGE_UNAVAILABLE`，不会降级为允许访问或泄露连接信息。

## 人工维护边界

先由迁移管理员建立既有 `novel_app` 角色，再应用 `packages/script/migrations/0002_workspace_model_access.sql`。应用角色只有 SELECT 权限，不能自行新增成员、变更角色或续期。业务服务只能使用受限角色；数据库账号不得提供给成员。

可信运维人员核验真实工作室及用户标识后，通过特权管理连接维护成员和订阅记录；所有参数必须绑定，不拼接用户输入。首次开通需要明确登记成员与高级订阅起止时间，不自动回填或赠送权限。续期更新到期时间，撤销设置 `enabled=false` 或停用成员。负责人转交应在同一短事务中停用/降级旧负责人，再设置新负责人，保持唯一有效负责人约束。运维变更审计与管理界面尚待实现，生产上线前必须补齐。

撤销只约束后续授权检查，不能承诺取消已在执行的请求。任务凭据解析、进行中任务撤销策略、密钥轮换和生产入口装配均属后续工作。

## 验证

`TEST_DATABASE_URL` 只能指向可丢弃测试数据库。集成测试创建权限表及随机测试工作室，并验证成员隔离、订阅到期、服务权限和应用角色不可自提权；未设置该变量时显式跳过。默认测试不使用真实模型 Key 或付费调用。
