# 局部重试任务与审核页

基线 2652726，接续只读 retry-plan。POST `/projects/:projectId/chapters/:chapterId/story-knowledge-tasks/retries` 接受且仅接受 `expectedActiveVersionId`、`scopeKeys`、`configurationVersionId`、`modelId`、`requestId`。沿用会话、项目成员、模型权限、大陆路由、许可、白名单和工作室队列限制。

服务端派生原文和失败来源任务，持久化 `input.retry={expectedActiveVersionId,retryOfJobId,scopeKeys}`，不接受客户端原文或来源任务。每个任务只对应一个来源，不能覆盖成功项。同一工作室/项目/章节/requestId 派生固定任务 ID，数据库主键负责并发去重；同一意图更换候选、范围或模型返回 409，原样重放返回同一任务（包括已完成任务），不再执行模型。requestId 每次明确的新意图生成，不是内容版本。

暂停任务的显式重提交保留 retry 快照，并重新核对候选、原文及模型。执行前再次检查失败范围/来源和活动候选；模型调用后再次检查原文、候选与许可。重试请求只列出所选范围，响应必须逐项匹配；非法结果不合并。现有 recordRetry 保留成功事实及人工决定，CAS 派生新候选，不自动确认。生产仓储在结果写入短事务中锁定当前章节原文及生成许可，避免检查到写入之间的竞态。

恢复根据持久化的重试结果幂等索引查找，使用精确任务、来源和范围；找到结果只修复任务状态，不调用模型。没有结果转 EXECUTION_UNCERTAIN，不允许暂停重提交。不同 requestId 是新的显式意图，去重不代表任意多个意图之间的唯一性。

审核页仅桌面提供失败复选框，选定来源后禁选其他来源，不可重试项禁用。模型需明确读取和选择。提交期间用同步锁阻止重复点击；网络或 5xx 结果未知时冻结参数，“核对原提交”复用相同 requestId。任务后台运行，页面显示状态；刷新可通过 URL 的任务编号在任务面板找回。任务完成后用户明确载入候选，校验当前原文、活动候选及精确任务结果，过期结果仅可任务面板只读查看。载入不会确认或解锁下游。

持久化复用现有 model_tasks JSON payload、主键和重试结果索引，无新迁移。生产装配仅在原有显式启用故事任务的分支注入规划器，不改变默认关闭。验证使用模拟供应商，无真实 AI；不包含平台积分计费或完整上线验收。
