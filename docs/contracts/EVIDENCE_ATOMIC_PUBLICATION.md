# 请求幂等与证据原子发布契约

日期：2026-10-07。范围：用户确认的文档与未来验收，不实现发布、迁移或真实扣费。

依据：[写服务授权](EVIDENCE_WRITE_AUTHORITY.md)、[结算证据](SETTLEMENT_EVIDENCE.md)。现有verifyPublish/verifySupplement只返回核验草稿；requestId没有持久化去重，isCurrent是点时检查，不能直接将草稿交给append宣称原子发布。

## 1. 请求身份与指纹

发布协议首版定义为evidence-publication-v1。唯一请求键为(workspaceId,requestId)，在publish/supplement之间共享命名空间。请求由可信宿主生成并持久保存到业务调用上下文，重试复用；服务身份/操作类型不得用于绕开同一请求冲突。新增业务动作（包括unknown后补证）必须用新requestId。

请求指纹为SHA256(规范化{protocolVersion,workspaceId,requestId,serviceId,operation,references,predecessorId})。对象键排序，数组保留顺序，null显式保留，禁止undefined/非JSON值；publish的predecessorId固定null。引用包含固定ID及版本，不包括当前价格/当前Key/活动版本。服务身份由宿主确定，不接受请求指定。

同唯一键、同指纹返回既存回执，不新增证据或审计；同键不同指纹返回CONFLICT，不覆盖。同请求切换操作、服务或前序也属冲突。服务轮换时找回旧请求应走另行授权的恢复能力，不能静默改写原服务身份。本协议不提供跨新requestId的业务去重；后续计费单元/事件约束仍必须防止新请求重复消费。

每次重放仍先验证当前工作室/专用操作权限。授权失效不返回既存证据信息；已提交且同指纹的重放可返回历史回执，不要求重新调用模型或依赖当前可变来源。无既存回执时必须重新核验来源，不能把先前客户端保存的草稿当可信输入。

## 2. 证据ID与回执

最终evidenceId由服务器计算：`evp_`加SHA256(JSON.stringify(["evidence-publication-v1",workspaceId,requestId]))的十六进制字符串。该ID只定位发布，不证明来源或权限；不同工作室互不混用。真实业务只有事务成功后才取得published回执。

核验草稿material.id只是来源准备阶段的占位标识，不决定最终ID。发布服务必须替换为协议ID后重新执行资料验证/指纹计算，并检查与前序不自引用。不得把旧草稿指纹用于新ID的资料；原始结果/执行ID保持不变。历史低层append记录不自动升级为published。

不可变回执至少含protocolVersion、workspaceId、requestId、evidenceId、requestFingerprint、materialFingerprint、operation、predecessorId、auditId、publishedAt。回执不含完整资料、小说或Key；由授权后台查询，非公开账单API。相同请求重放返回原publishedAt和auditId。

## 3. 原子保存对象

| 对象 | 不变量 |
| --- | --- |
| 请求映射 | (workspaceId,requestId)唯一、请求指纹固定、最终证据关联唯一，不得覆盖 |
| 证据资料 | (workspaceId,evidenceId)唯一、重验后的material/指纹/前序；沿用不可变规则 |
| 审计关联 | 固定写服务、来源ID/版本/指纹、验证规则、核验时间及一致性证明引用；指向同请求/证据 |
| 发布回执 | 与请求/证据/审计一一对应，只在同事务提交后可用，不单独提前返回 |

四项必须在同一PostgreSQL事务提交；补证还需核验同工作室既存前序及固定绑定/快照/执行。任一步失败全部回滚，不能留下有资料无审计的可用发布。现有PostgresEvidenceMaterialRepository.append拥有自己的事务，不能通过先append后写请求/审计实现此边界；未来须新增共同事务发布仓储接口。

只读生产读取必须识别已提交发布关联，验证资料指纹与审计/回执一致；裸资料行不能仅因存在就视为已核验生产证据。当前只读服务尚无该发布门禁，未来接生产前需升级或另建发布读取接口，历史测试夹具不能自动变成生产凭证。

审计关联独立保存，不向现有formatVersion=1或九字段投影增加未支持字段。映射、审计、回执只追加，无公开改删；数据保留与删除权限另行批准。总容量、字段/引用数量上限及迁移计划在实现时明确。

## 4. 来源变化与发布一致性

核验与提交之间必须有可验证的来源一致性屏障，保护任务计费快照、执行记录、完整原始结果集合及校验/计价记录。仅在提交前远程调用isCurrent一次不够：检查之后仍可能变化或出现第二个结果。

允许的实现边界：来源与发布同数据库时，在共同事务中以锁/版本条件保护来源版本及结果集合唯一性；外部来源必须先提供可审计的不可变封存清单与完整性证明，且封存后不能追加冲突结果。具体屏障机制尚未交付，无法证明时拒绝发布，不能降级为点时检查。

不得在长数据库锁内调用模型、解密Key或执行无界远程请求。前置读取可在事务外完成，但最终事务必须核验受保护的版本/封存证明。前序也由最终事务核验。来源不可用、变化、缺失或冲突默认拒绝，不能伪造failed/unknown；不允许从新活动版本自动改引用以“修好”旧请求。

## 5. 并发与故障恢复

并发竞争同请求：以唯一键/受控锁收敛，一个提交胜者。失败事务整体回滚，另一方授权并核对指纹后返回原回执或CONFLICT。不能无条件ON CONFLICT DO UPDATE覆盖历史。不同请求若共享单元且结论冲突，发布不自动裁决或改账本，仍需来源唯一性/对账规则。

数据库提交结果不确定（断网、COMMIT响应丢失）返回净化的待核对错误，保留原requestId；通过授权lookup(workspaceId,requestId)检查完整提交。未读到回执时不能仅据此宣布未提交或换新ID；恢复发布仍使用原身份，让数据库唯一约束处理在途竞争。不得再次调用生成模型。

超时分为语句/锁等待/整个任务截止，不以5秒statement_timeout等同整个事务5秒。失败若确定回滚可重做来源核验；重放引用保持固定。通知/Outbox及账本应用尚不包含在本协议四项事务中，证据published不等于积分已消费。若未来需要事件投递，应另行纳入Outbox或可靠扫描，不依赖提交后的临时内存通知。

## 6. 未来验收（本轮未执行）

| 编号 | 场景 | 预期 |

| P01 | 同工作室同请求同引用重复/并发发布 | 一个证据/审计/回执，重放回执完全一致 |
| P02 | 同请求改引用、服务、操作或前序 | CONFLICT，原四项不变 |
| P03 | 两工作室相同requestId | 分别独立身份/证据ID，授权读取隔离 |

| P06 | 草稿核验后来源变化/出现第二个原始结果 | 屏障拒绝提交，不能只依据旧isCurrent |
| P07 | 外部来源只有点时token、无不可变封存证明 | 不允许生产发布 |
| P08 | 前序不存在、跨工作室或快照/执行改变 | 整体拒绝，无孤立请求或资料 |
| P09 | COMMIT已成功但响应丢失 | 原请求lookup/重放找回原回执，不再生成/发布第二份 |

| P11 | 当前权限撤销后的旧请求重放 | 返回拒绝，不泄露原证据/审计 |
| P12 | 低层append已有裸资料但无发布关联 | 不能视为生产published证据 |
| P13 | 已提交同指纹请求，当前来源暂不可读 | 授权重放历史回执，不改成失败或补扣 |
| P14 | 发布成功、账本应用失败/通知丢失 | 回执仍是证据发布成功，计费/投递各自恢复，不宣称已扣费 |

## 7. 下一实施边界

用户已选择同数据库路线A，来源集合、observation/final封存、迟到结果、共同锁序与发布读取门禁设计见[EVIDENCE_SOURCE_SEAL](EVIDENCE_SOURCE_SEAL.md)。来源封存内存规则夹具已交付，真实Writer屏障和PostgreSQL共同发布事务尚未实现。完整来源、关闭证明及适配接口新增设计见[EVIDENCE_TRUSTED_SOURCE_TRANSACTION](EVIDENCE_TRUSTED_SOURCE_TRANSACTION.md)，新协议版本仍待确认，不改写既有v1指纹。

增量已交付协议ID/请求指纹、原子发布仓储接口、内存复合记录和授权服务规则夹具。复合记录包含请求/资料/审计/回执，提交前完整校验、一次保存，无独立append；记录查询及重放仍经专用授权。只使用可信封存资料夹具，sourceSealId不构成生产证明，没有真实来源屏障、持久化事务或发布读取门禁；P01～P14不视为已全部验收，不能将内存发布回执用于真实扣费。

后续先确认完整来源与共同事务的新协议/测试接口，再实现规则夹具和PostgreSQL共同事务与发布读取门禁；不能直接从现有内存发布切换生产。实库验证须包含响应丢失、回滚和并发来源登记，禁止复用点时草稿绕过屏障。
