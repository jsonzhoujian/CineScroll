# 模型任务记录与状态流转（基础层）

`ModelTaskService` 通过可信 `ModelTaskContextReader` 获取已授权项目的原文版本、按序排列的上游确认版本及生成参数。Reader 必须验证项目权限和阶段前置条件；不能直接用客户端对象代替。只保存版本引用和固定参数，不复制可变原文，也不保存 Key、密文或供应商响应。Worker 后续必须按这些版本引用读取不可变内容。

`submit` 使用当前已测试配置生成任务模型快照，任务从 `queued` 开始。`run` 通过 revision CAS 抢占为 `running`，再次比较上游输入并调用可信凭据执行边界。正常完成为 `succeeded`；模型配置变化、权限/订阅失效、模型未就绪或上游变化为 `paused`，记录稳定原因；供应商失败为 `failed`。暂停或失败必须有非空原因。历史任务不能返回 queued 或自动换 Key。

`resubmit` 只接受 paused 任务。当前原文版本、上游确认版本和参数必须与旧任务一致，否则返回 `UPSTREAM_CHANGED`，要求重新发起生成。成功会创建 queued 子任务，保留旧任务原输入及记录，仅选择新模型快照；一个父任务最多一个子任务，重复提交返回 `STATE_CONFLICT`。子任务再次暂停时可以从子任务继续创建后继。

`PostgresModelTaskRepository` 配合 `0003_model_tasks.sql` 提供持久化、工作室 RLS、同工作室父任务外键、唯一后继、CAS 和不可变输入约束。应用只可 SELECT/INSERT 和更新状态相关列，不能修改原输入或删除任务。数据库访问仍是内部服务权限，不替代项目访问检查。状态记录目前只存当前状态/revision，不是完整的操作事件审计。

回调只接收服务器解密的凭据、jobId 和输入引用，不返回模型响应给任务记录。阶段 Adapter 必须验证模型能力及结构化响应、实现 jobId/scope 幂等、生成候选内容；本基础层不证明生成成功的业务质量。

可信回调可返回严格的候选版本指针和 extractionStatus（不是供应商响应）。0004_model_task_results.sql 将 result_json 与终态同次 CAS 更新，旧任务保持 null；细分 INVALID_RESPONSE/CANDIDATE_EXISTS 失败及在途 UPSTREAM_CHANGED 暂停。受控错误仅保留枚举，其他异常仍净化，不保存凭据或厂商错误消息。此更新不让候选写入与任务终态成为同一事务。

## 尚未交付

故事知识阶段已有 opt-in HTTP 入口及实际项目 ContextReader，详见 STORY_KNOWLEDGE_TASK_API.md。尚无前端列表、自动调度/轮询、租约、崩溃恢复、计费、任务级境外授权或真实生成，也未挂载生产模块。服务/存储失败后任务可能停留在 running；不得自动重新发出可能已计费的请求。运行期间上游变化不取消已发出的调用，候选内容落库还需版本校验。此基础层不能称为可上线的可靠队列。

## 验证

默认测试使用内存仓储；设置 `TEST_DATABASE_URL` 时才应用迁移并执行真实 PostgreSQL 测试，只允许可丢弃管理员测试库。相同服务契约覆盖旧 Key 暂停、新任务保留输入、唯一后继、并发只执行一次、上游变化拒绝及工作室隔离；另验证应用不能修改 payload/删除任务，以及数据库拒绝无原因暂停。测试夹具留在临时数据库，不连接业务数据库或模型厂商。
