# 测试策略

状态：T03 评审稿  
日期：2026-09-22

## 1. 测试金字塔

1. **Schema 测试**：所有 canonical JSON、AI 请求和响应夹具。
2. **领域单元测试**：状态机、门禁、权限、锁定、影响分析、时长和证据规则。
3. **模块集成测试**：PostgreSQL 事务、Outbox、队列、对象存储和积分流水。
4. **Provider 契约测试**：使用录制/模拟响应验证适配，不在 CI 调用付费模型。
5. **API 测试**：租户隔离、鉴权、乐观锁、幂等键和错误语义。
6. **端到端测试**：以玄幻、都市、悬疑夹具跑完整纵向流程。
7. **探索与用户验证**：内部测试持续执行；T01b 在可操作 MVP 后执行。

## 2. 必须自动化的领域不变量

- 阶段结果四种类型各出现一次，直接上游确认后才允许生成下一阶段正式内容。
- `activeVersionId`、`confirmedVersionId` 和引用 ID 存在且类型/租户一致。
- 已确认版本必须有确认人和确认时间。
- 每个正式条目有原文出处或批准的改编新增。
- 锁定条目不在重新生成覆盖范围内。
- 部分成功同时包含成功项与失败项；完整成功不得含失败项。
- 镜头总时长与目标时长偏差不超过 10%。
- 建议接受/拒绝和阶段确认操作幂等。
- 同一积分业务键只能冻结、结算或退款一次。
- 工作模式切换不改变 canonical content version。

## 3. 安全测试

- 每个资源 API 都测试跨租户读取、写入、导出和对象 URL 获取。
- 编辑、审核人、负责人权限矩阵覆盖正反例。
- 上传测试 MIME 伪造、超限、压缩炸弹、DOCX 外部引用和路径穿越。
- BYOK 测试密文存储、日志脱敏、错误脱敏、轮换和删除。
- 验证码测试频率限制、重放、过期和账号绑定冲突。
- 导出文件测试公式注入、恶意文件名和未确认内容标识。

## 4. AI 与异步任务测试

- FakeProvider 支持成功、部分成功、非法 JSON、超时、限流和重复回调。
- Worker crash 后 lease 回收，重试不重复写入或计费。
- Outbox 重放不创建第二个业务任务。
- 供应商请求必须使用不可变输入快照和对应 Schema 版本。
- 模型输出先存隔离区，校验通过后才转为候选版本。
- 局部重试只发送失败 scope，不包含已成功、确认或锁定项。

## 5. 三模式一致性测试

- 给定相同项目版本与工作游标，追溯、审核、分镜读取相同 ID 和状态。
- 切换模式仅改变 `workMode`，内容版本哈希不变。
- 镜头定位到多个剧本元素或原文时显示集合，不任意覆盖选择。
- 未满足门禁时后续模式显示空状态/只读已有内容，不展示伪正式候选。
- 已处理建议和已确认阶段在所有模式同步显示最终状态。

## 6. 夹具与回归样本

- 玄幻：世界规则、别名、灵气状态、关键道具。
- 都市：现实地点、电话事件、多角色对白。
- 悬疑：隐藏身份、矛盾事实、信息延迟披露。
- 每类至少一个合法项目、多个非法变体和固定期望输出。
- 授权/自有长文本不得进入公开仓库；CI 使用最小合成夹具。

## 7. 发布门禁

### 每次合并

- 格式、类型、单元、Schema、模块集成、安全静态检查通过。
- 数据库迁移可向前执行并经过空库与旧快照测试。
- 不允许真实 API Key 或作品原文进入仓库和日志快照。

### 封闭内测发布

- T04～T09 对应验收场景通过。
- 删除/恢复、积分对账、任务恢复和导出回归通过。
- 监控、告警、备份恢复演练完成。

### 收费上线前

- T01b 至少 5 家工作室验证完成。
- 至少 3 家在 14 天内复用并表达付费意愿。
- 全部阻断和高严重度发现已关闭或有明确风险接受。
