# 项目章程：AI 小说影视化工作台

## 立项目标

建立一套 SaaS 工作流，把用户已有的小说或故事转化为可编辑、可追溯的剧本、设定与分镜，并为后续图片和视频生成提供结构化输入。

## 问题陈述

小说中的环境、心理、世界观与叙事信息不能直接交给视频模型。当前工作通常依赖创作者手工完成内容理解、剧本改编、视觉设定、分镜拆解和提示词编写，流程耗时、容易遗漏，且人物和设定难以跨章节保持一致。

## 产品承诺

用户导入一章小说或一个故事片段后，可以得到：

1. 可核对原文出处的人物、场景、道具、事件和世界规则。
2. 可编辑并确认的场次剧本。
3. 可复用的角色、场景、道具与画风设定。
4. 可编辑的结构化分镜。
5. 少量可由外部模型生成的视频镜头。
6. 可带走的剧本、分镜和素材文件。

## MVP 纵向切片

```text
导入一章小说
→ 识别章节和原文片段
→ 提取故事知识
→ 用户确认
→ 生成场次剧本
→ 显示原文与剧本映射
→ 生成 20～40 个分镜
→ 生成 3～5 个关键镜头
→ 导出剧本与分镜
```

## MVP 范围

### 包含

- TXT、DOCX 或粘贴文本导入
- 章节与段落识别
- 人物、场景、道具、事件和世界规则提取
- 原文证据与置信状态
- 场次剧本生成、编辑、确认和锁定
- 角色、场景、道具和全局画风设定
- 结构化分镜及预计时长
- 外部图片/视频模型适配层
- 异步生成任务、失败重试和成本预估
- 剧本、分镜和素材导出

### 不包含

- AI 故事或小说原创
- 自动续写
- 小说发布或连载
- 整本小说一次自动影视化
- 120 分钟电影一键生成
- 自由节点画布
- 专业非线性剪辑器
- 自建基础模型或 GPU 集群
- 原生移动 App
- 多人实时协作

## 初始目标用户假设

第一批用户暂定为需要将已有网文或故事制作成动态漫、漫剧或短视频的小型创作者和工作室。该假设需要通过访谈验证。

## 成功指标

- 用户可以在 30 分钟内从一章原文获得第一版可编辑剧本。
- 核心人物和关键事件可追溯至原文。
- 用户能在局部重生成时保留已锁定内容。
- 用户能在产生视频费用前看到预计成本并确认。
- 从导入到导出形成一条可完成的纵向流程。
- 试用用户愿意使用该流程完成第二个项目。

## 质量指标

- 核心情节覆盖率
- 人物及场景遗漏率
- 虚构重要事实率
- 提前剧透率
- 分镜时长偏差
- 单镜头可用率
- 平均重试次数
- 每成片分钟的模型成本

## 原则

- 原文永久保留且可追溯。
- AI 输出默认是候选内容，不自动成为故事事实。
- 用户确认和锁定优先于模型建议。
- 修改上游内容只标记下游受影响项，不自动产生费用。
- 文本、图片和视频模型均通过可替换适配层接入。
- 首版优先验证完整工作流，不追求功能数量。

## 主要风险

- 长篇解析在层层摘要中丢失重要事实。
- 人物别名、隐藏身份和时间线被错误合并。
- AI 改编偏离原著或过度压缩环境内容。
- 视频生成可用率低导致成本失控。
- 第三方模型调价、限流或下线。
- 小说版权、真人肖像、声音与生成素材授权不清。
- 用户愿意尝试但不愿持续付费。

## 当前阶段
