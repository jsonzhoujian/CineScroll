# 低保真原型内部探索测试与测试需求

状态：第一轮完成  
日期：2026-09-22  
测试性质：产品团队内部探索，不计入真实工作室样本

## 1. 测试目的

在正式开发前验证低保真原型能否自洽地表达四阶段流程、三种工作模式、原文追溯、修改建议和分镜审核。该测试用于发现状态模型与交互表达问题，不用于证明市场需求、真实用户可用性或付费意愿。

## 2. 测试范围

原型入口：`http://localhost:4173/?mode=trace`

本轮实际执行：

1. 查看四阶段状态和当前阶段。
2. 在追溯模式接受修改建议。
3. 切换至审核模式，检查选择、建议状态和阶段状态。
4. 确认剧本阶段。
5. 切换至分镜模式，检查共享状态。
6. 选择 `04-05 马车离阁`，检查镜头详情和原文定位。

未纳入本轮：真实文件导入、AI 生成、版本差异、局部重试、导出、权限、计费和合规流程。这些功能尚无可操作原型。

## 3. 本轮结论

### 3.1 已验证成立

- 三种模式入口清晰可见，可以自由切换。
- 模式切换后内存中的阶段、已确认列表、当前原文、当前镜头和建议状态没有整体重置。
- 分镜选择能够更新镜头详情和对应原文标识。
- 剧本确认会写入共享的 `approved` 状态，并在审核模式阶段列表中显示已确认。

### 3.2 发现的问题

| ID | 严重度 | 发现 | 风险 | 对应要求 |
| --- | --- | --- | --- | --- |
| INT-01 | 高 | 修改建议已接受后，审核模式仍显示“1项建议待处理”，接受/拒绝按钮也继续存在 | 用户可能重复处理同一建议，状态表达互相矛盾 | FR-008b、FR-008c、FR-139 |
| INT-02 | 高 | 剧本确认后仍显示“确认剧本并解锁设定”按钮和确认前说明 | 用户无法判断操作是否成功，可能重复确认 | FR-045、FR-131、FR-139 |
| INT-03 | 高 | 分镜模式会直接展示“正式分镜待确认”，但共享状态显示当前仍是剧本阶段，设定也未确认 | 工作模式可能绕过阶段门禁，混淆“查看示例”和“生成正式内容” | FR-053、FR-131、FR-140 |
| INT-04 | 高 | 切换工作模式时，顶部阶段可能被模式强制显示为剧本或分镜，与 canonical `stage` 状态不一致 | 用户容易把工作模式误认为生产阶段 | FR-137～FR-141 |
| INT-05 | 中 | 选择镜头后更新了 `selectedShot` 和 `selectedSource`，但 `selectedBlock` 未同步，追溯检查器内容仍为硬编码示例 | 跨模式返回后可能显示不一致的剧本块、镜头和来源 | FR-061、FR-133、FR-139 |
| INT-06 | 高 | 目标单集为 3 分钟，但示例分镜总时长只有 22 秒，界面没有显示偏差或阻断提示 | 用户可能误以为当前分镜满足时长验收 | BR-008、QR-004 |
| INT-07 | 中 | “仅看剧本”“改编报告”“提交修改建议”等控件没有产生可观察状态变化 | 测试参与者无法区分原型未实现与产品逻辑不成立 | 原型测试完整性 |
| INT-08 | 中 | 当前原文高亮、镜头高亮、剧本块高亮没有统一显示一个“当前工作上下文”摘要 | 用户难以确认跨模式切换究竟保留了什么 | FR-139 |

上述发现只证明原型内部存在自洽性问题，不代表真实工作室一定会遇到相同问题。

## 4. 原型修订优先级

### P0 — 进入架构设计前必须明确

1. 工作模式与生产阶段必须是两个正交状态：模式只改变布局，不能修改或伪造阶段。
2. 未满足阶段门禁时，后续模式只能展示只读示例、空状态或“尚未生成”，不能展示为正式待确认内容。
3. 修改建议与阶段确认必须是幂等状态转换；完成后所有模式立即显示相同结果。
4. 当前上下文必须由统一游标表达：章节、集、场次、剧本块、镜头和原文片段之间的映射不得局部更新。

### P1 — 下一轮可操作原型必须补齐

1. 建议处理后的状态、处理人和处理时间。
2. 已确认阶段的只读状态、重新打开版本的入口和下游解锁结果。
3. 分镜总时长、目标时长、偏差百分比和阻断原因。
4. 未实现控件必须禁用或标注“原型暂不可用”。
5. 三种模式均显示当前阶段和当前工作上下文，但不重复保存它们。

## 5. 正式实现的测试需求

### TR-01 模式切换不改变权威内容

- 给定同一项目、内容版本和工作游标，切换追溯/审核/分镜模式后，canonical project state 哈希不变。
- 只允许用户偏好中的 `workMode` 改变。

### TR-02 工作游标连续性

- 从剧本元素切换到分镜模式时，系统定位关联镜头；存在多个镜头时显示候选而不是任意选择。
- 从镜头切回追溯模式时，系统显示其剧本元素和全部原文依据。
- 无映射时必须显示明确空状态，不沿用上一次选择。

### TR-03 阶段门禁

- 故事知识未确认时不得生成正式剧本。
- 剧本未确认时不得生成正式设定。
- 设定未确认时不得生成正式分镜。
- 用户仍可进入任一工作模式，但只能看到已有正式内容、只读示例或受限空状态。

### TR-04 建议状态一致性

- 建议接受或拒绝后，所有模式中的待处理数量、按钮、状态、处理人和处理时间一致。
- 对已处理建议重复提交同一决定必须幂等，不得产生第二次正式修改。

### TR-05 阶段确认一致性

- 阶段确认后，确认按钮转为已确认状态，不再重复提供相同动作。
- 确认操作必须记录确认人、时间和确认版本。
- 下一阶段只在确认成功后解锁。

### TR-06 追溯完整性

- 每条故事知识、对白、动作、设定和镜头至少关联一个原文片段，或标记为已批准的改编新增。
- 点击任一目标时，来源高亮、检查器摘要和 canonical 引用 ID 必须一致。

### TR-07 时长验收

- 分镜总时长自动求和并与 1/3/5 分钟目标比较。
- 偏差超过 10% 时禁止确认完整分镜，并指出需要补充或压缩的范围。

### TR-08 部分失败与局部重试

- 成功项保留，失败项展示原因。
- 重试范围只包含失败项，不覆盖已确认或锁定项。
- 同一幂等键重复回调不得重复写入或重复计费。

### TR-09 版本与影响

- 修改已确认上游内容产生新版本，并列出下游受影响项。
- 系统不得自动覆盖锁定内容。
- 用户明确选择后才重新生成指定范围。

### TR-10 权限

- 编辑只能提交已确认内容的修改建议。
- 负责人和审核人可以处理建议、确认阶段和锁定内容。
- 未授权操作在客户端和服务端均被拒绝。

### TR-11 可访问性与键盘操作

- 工作模式、阶段、建议和镜头按钮具有可读名称、选中状态和焦点状态。
- 键盘切换不能在文本输入时误触发。
- 状态变化通过可访问的实时提示告知用户。

### TR-12 响应式范围

- 桌面完整编辑最低按产品确定的支持宽度验收。
- 移动端只显示进度、审核、建议处理和通知；不得误露出不可用的完整编辑入口。

## 6. 后续验证分层

1. **当前阶段**：公开资料研究验证行业工作流与历史痛点；内部探索测试验证原型自洽性。
2. **架构与开发阶段**：契约测试、状态机测试和端到端测试验证系统行为。
3. **可操作 MVP 阶段**：邀请 5～10 家工作室完成真实任务，验证可用性、流程契合度和复用意愿。

因此，真实工作室测试不再作为开始 T03 架构设计的前置条件，而作为封闭内测与产品验证的必要条件。
