## 切片二至四：接通实现（本轮，基线 2652726）

- ModelTaskService.submitRetry 使用服务端 readRetry 生成可信快照，以 requestId 派生固定任务 ID；原样重放返回同一任务，变更意图返回冲突。
- 复用现有 JSON 持久化、队列上限和唯一主键，无迁移；读回快照及租户隔离在临时 PostgreSQL 验证。
- Executor 支持 scoped retry 和无模型恢复；仅传递选中范围，沿用 recordRetry/CAS 保留已成功和人工决定，原文/候选变化阻止合并。
- 生产重试写入补充同事务当前原文/许可保护；数据库测试先证实旧原文写入原本未拒绝，再补保护通过。
- 审核页使用版本键隔离异步结果，桌面选择同来源范围及已测试模型；固定提交意图处理未知结果；显式载入新候选，不确认。
- 复用已有生产故事任务开关，默认关闭；测试不调用真实模型。

最终验收：Node 全量 163 通过、9 跳过、0 失败；浏览器 21 项通过，含同来源选择、不可重试禁用、未知提交复用意图、过期候选拒绝载入、移动端只读。临时 PostgreSQL 专项套件 9 项通过（包括领域回归及实库用例），验证 JSON 快照重建可读、租户隔离、额度=1 同意图并发去重及旧原文/受限许可写入拒绝。四个受影响包的 TypeScript 和 diff 检查通过，截图人工检查完成。

Spec 复审发现容量触发器可能先于唯一主键拒绝同意图并发，已用公开上下文屏障稳定复现红灯，并在 TASK_QUEUE_FULL/STATE_CONFLICT 后核对固定 ID 修复为绿灯。Standards 建议已落实：共享短事务门禁、轮询失败可手动刷新原任务。两轴最终无剩余阻断。没有真实 AI、业务数据库迁移或推送；临时数据库服务已在验证结束后停止。详见 STORY_KNOWLEDGE_RETRY_TASK.md。
