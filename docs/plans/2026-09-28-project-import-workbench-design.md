# 项目与章节导入工作台设计

## 目标与边界

本轮完成 T04 的最后一个用户可见切片，让中国大陆小型动态漫工作室从登录开始，完成项目创建、改编权声明、小说章节预检、单章导入、原文查看和重新导入差异检查。页面不生成故事知识、剧本、设定或分镜；这四个阶段与追溯、审核、分镜三种工作模式仍作为共享项目状态的导航出现，但未生成能力必须明确标记而不是伪造结果。

## 交互结构

界面采用一个连续工作台，而不是多页向导。左侧“卷轴”展示五个可恢复步骤：登录、项目、原文、章节、版本；主区域只呈现当前任务，右侧保持项目约束和处理说明。手机号登录先获取服务端签名设备 token，再发送和验证验证码。创建项目必须勾选改编权声明，并选择 9:16/16:9、1/3/5 分钟和旁白型/对白型。原文输入允许粘贴以及 TXT/DOCX 文件；文件仅在用户点击预检时读取并编码，不提前上传。预检结果展示识别章节、字数和可选状态，用户明确选择一章后才能正式导入。

导入完成后切换为双栏原文工作台：左侧显示章节与活动版本，右侧显示不可静默覆盖的原文片段、稳定片段 ID、版本元数据。重新导入使用同一文本输入，成功后展示新增、删除和未变化段落，并保留旧版本序号。错误按照 API 机器码翻译为可恢复提示；认证失效返回登录入口，合规服务不可用允许重试，超长章节保留预检结果但禁止导入。

## 技术与验收

使用 Next.js App Router、React 和 TypeScript。API 调用封装在单一客户端中；Session 仅保存在当前页面内存，不写入 localStorage。首个组件测试覆盖项目选项和改编权门禁，浏览器验收覆盖手机号登录、项目创建、粘贴多章、章节选择、导入和重新导入差异。桌面为三栏编辑台；移动端降级为纵向步骤与只读结果，符合 MVP 移动端不做完整编辑的范围。
