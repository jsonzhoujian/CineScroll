# T06-05 正式剧本修订实施计划

状态：T06-05 已完成。下文逐轮记录为历史过程，以末尾最终验收为准。基线 `c14dd1b`。任务验收以 `.scratch/novel-adaptation-mvp/issues/t06/05-revise-confirmed-script.md` 为准。

## 已确认约束

负责人、审核人可以处理建议；编辑成员仅提出建议。正式修改须派生候选并重新通过 T06-04 质量确认。锁定元素必须先明确解锁。任何建议都绑定精确正式版本和原文来源，不得静默套用到新版本。拒绝建议不改变作品内容。

## 实施顺序

1. 在 ScriptContentRepository 增加历史版本与正式版本读取；迁移增加独立 confirmed_version_id 并从已有正式 active head 回填。修订候选仅改变 active 指针；确认事务才推进正式指针。历史、正式读取保持租户和项目成员隔离。
2. 在公开领域服务增加正式建议、裁决、解锁命令。沿用请求 ID、指纹、理由、操作者与不可变快照审计；同请求恢复原结果，不返回另一请求的成功记录。解锁仅移除明确目标的锁属性，数据库守卫仍拒绝无关内容变更。
3. 建议接受后派生修订候选，保存正式来源、建议身份及变更元素；清除旧报告绑定与确认元数据，保留原文证据和未涉及元素的锁。跨版本、已锁定、并发修订均拒绝，不隐式重放建议。
4. 重新评估、确认复用 ScriptPublicationService。正式指针、变更记录及下游受影响项在同一事务提交；失败回滚。受影响项使用 DOMAIN_MODEL 的 unreviewed 状态，只标记，不自动重做，也不清除下游锁。
5. API 提供成员可读的历史、正式内容和影响记录，以及按角色执行的修订命令；页面明确展示当前正式版与待确认候选，支持提出/裁决建议、解锁、重新评估确认和原文追溯。
6. 沿用已确认的 API、Worker、仓储和浏览器测试边界，覆盖历史读取、正式指针保留、锁定拒绝、跨版本建议拒绝、并发请求与未知结果恢复。跑隔离 PostgreSQL/TLS、类型检查、必要完整回归和 Standards/Spec 双轴审查，再更新 README、总表与交付计划。

## 范围
