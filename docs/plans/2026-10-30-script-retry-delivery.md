# T06-03 剧本失败范围重试交付

日期：2026-10-30。基线：`3cd2263a9b9c1f7dd096f025f9e4d5d0d96ee1f1`。按用户要求保留工作区修改，不自动提交。

## 行为与边界

用户在当前剧本候选中选择可重试失败项和已测试的大陆模型，明确提交局部重试。成功内容、未选择失败项、已有场次、修改建议及原文依据保留；完成后由用户明确载入结果。界面区分本次成功、本次仍失败和其余失败范围，并按集、场次及元素的 ordinal 展示，避免恢复较早内容后出现倒序。

服务端仅接受当前可重试失败 scope，绑定原文、已确认知识、拆集方案、项目参数和精确候选版本。模型只收到失败目标、正式上游和原文上下文，以及只读场次身份/顺序；不发送现有成功元素作重试目标。返回范围必须恰好覆盖所选项。既有元素 ID/排序位置碰撞被隔离为失败，既有场次不得被改写，已确认内容禁止重试。

所有返回项经过现有 canonical 校验后才合并。合并只提交一次不可变新版本，使用 CAS 和事务上游锁；生成期间的人工编辑、上游变化和旧结果均不能覆盖新版本。重试新版本保留建议，移除不属于本次生成的审核命令身份，原生成结果索引仍指向任务的原始快照。

## 请求、来源与恢复

新增 Session 保护的 `POST projects/:projectId/chapters/:chapterId/script-content-tasks/retries`，只接受模型选择、requestId、expectedActiveVersionId 和 scopeKeys，不接受客户端提供作品正文或上游身份。沿用共享生成限流与工作室/供应商准入，响应 no-store，无公开执行或恢复接口。

同一请求的重放返回原任务，候选变化后仍可先通过成员读取门禁核对原请求。每个候选最多有一个 queued、running 或 EXECUTION_UNCERTAIN 重试，避免不同请求 ID 对同一候选并发付费执行。UI 在提交结果未知时冻结选择，刷新/重新登录后沿用原请求；已知执行结果未知时也禁止再次提交。

`retryOfJobId` 表示候选的聚合父生成任务；每个失败项的 `originJobId` 记录真实失败任务，任务快照 `failureOrigins` 固定所选范围的真实来源。未选失败项不因其他范围重试而改变来源，选中后再次失败才归属本次任务。连续两轮不同范围的来源链有独立回归。

模型或存储结果未知时进入 EXECUTION_UNCERTAIN；包括模型返回后进一步读取上下文失败。恢复只核对已存的精确合并快照和范围/来源，不重新调用模型。技术失败、超时及重试状态都不直接作为积分退款证据，T09 结算门禁保持不变。

## 持久化与契约

迁移 `0015_script_retry.sql` 增加同候选未完成重试唯一索引和版本重试元数据基本约束，并加入只读启动预检。scope 字符串、去重、可重试范围与来源语义由服务层校验，不将数据库基本形状约束宣称为完整业务验证。迁移须由可信管理员在前序迁移后应用；本轮仅应用于新建隔离实例，没有业务库或生产部署变更。

AI 请求 Schema 增加仅 script 可用的只读重试上下文，要求顶层父任务引用，包含场次身份和 ordinal。合法请求及禁止夹带成功元素的非法请求夹具均经 Draft 2020-12 校验。
