## D1b 初始化权限验收

在全新的仅 Unix socket 的隔离 PG16 实例中，测试专用门禁按固定 SHA-256 指纹读取初始化角色、成员关系、四张表的策略、函数定义、对象及列 ACL 和默认 ACL。读取范围为初始化及其依赖 schema、全局默认 ACL 和初始化角色配置。指纹以对象和角色名比较，排除角色 OID。现有 SQL 草稿和旧门禁沿用原有配置。

实库 255 项通过。配置通过后，分别验证角色继承、角色成员关系、策略表达式、辅助函数属性、列授权、表撤权及全局默认授权共七类漂移。每次变更在独立事务回滚，并复验基线。撤回初始化扩展后，旧私有门禁恢复通过。计费基线 148 项通过、11 项跳过。

## D1b 初始化写入材料

隔离 SQL 草稿新增内部 `prepare` 函数。它从私有核验结果和原命令派生集合、两条来源、两条类型关联、回执和两条回执成员，复用已冻结编码和预算公式。函数按调用者权限运行，测试在隔离 fixture 管理员下构造材料，并验证 inspector 无执行权限。未来受控写入口必须在同事务取得真实私有核验结果，固定集合 ID 与提交时间，才可调用该函数。

实库回归逐项比较八份结构化材料，并匹配集合包 4,321 字节和回执 4,085 字节。实库拒绝命令与核验引用错配；使用固定合成核验向量比对投影结果。隔离 PG16 全套 256 项通过。

## D1b 首笔受控写入

在隔离 PG16 中，普通服务 LOGIN 仅获准调用初始化入口。入口由非登录且无 BYPASSRLS 的角色持有。它锁定当前授权和预算，复用私有业务核验和写入材料构造，再写入集合、两条来源、两条类型关联、回执、两条成员及预算。沿用 FORCE RLS 和 ALWAYS 触发器，每笔首写仅允许两条来源及一份回执对应的预算增长。

独立连接验证提交前读不到本次写入、提交后所有记录和预算共同可见。注入回执约束故障后，独立连接观察到全部记录和预算回滚。服务身份错配、直接读写表、切换到 initializer 及调用准备函数均被拒绝。撤回测试扩展后原有私有门禁仍通过。隔离 PG16 全套 257 项通过，计费回归 148 项通过、11 项跳过，计费类型检查通过。

## D1b 原键历史重放

受控入口先锁定当前授权，再按原键比对规范命令及其指纹。相同命令核验原回执、两个有序来源及其类型关联，返回原回执。同键异命令返回 CONFLICT。历史读取先于预算锁。首次查询未命中时，取得预算锁后再查一次，以吸收并发首写的结果。

隔离双连接测试确认第二次调用确实等待首笔事务，提交后两次结果完全一致，集合、回执及预算只增加一次。已有回执在预算行被独立锁住时仍可重放，撤销服务授权后则拒绝。隔离 PG16 全套 257 项通过。计费回归 148 项通过、11 项跳过，计费类型检查通过。

## D1b 提交结果未知后的恢复

隔离调用端只在收到 COMMIT 确认后交付回执。提交确认丢失时返回 UNAVAILABLE 并销毁连接，显式重试复用首次序列化的命令，无自动重试。测试在两份独立工作空间分别终止提交前和提交后的真实 PG16 后端。前者在重试前无回执和预算增量，重试后正常生成。后者复用原回执，即使调用方已修改原输入对象。两种路径各保留一份回执、两条来源和一次预算增量。

隔离 PG16 全套 257 项通过。恢复接口目前位于测试支持层。T09 仍为 ready。

## D1b 异键同集合登记与容量边界

既有集合经当前授权、固定引用、来源及类型关联复验后，新 ingest ID 返回 already_registered。只新增回执与两条有序回执成员，集合头及来源预算保持原值。引用或内容冲突返回 CONFLICT，超出初始生命周期返回 STATE_BLOCKED。原键重放继续返回历史回执。

异键回执的结构和计量与黄金向量一致，固定向量为 4,113 字节。隔离夹具验证回执总预算恰好达到 16 MiB 和 1,024 份时可以提交，字节超限 1 时写入整体回滚，满额后原键仍可重放。隔离 PG16 全套 257 项通过，计费类型检查通过。

## D1b 写入权限配置与隔离装配

独立检查角色从同一 Unix socket 的隔离 PG16 数据库读取目录。冻结指纹覆盖初始化及依赖 schema、相关角色与成员关系、对象及列 ACL、默认 ACL、RLS 策略、触发器、约束和函数定义。装配时验证检查角色与服务角色的实际会话身份，服务连接每次借出前复验指纹。权限、策略或触发器漂移时拒绝装配及后续借用，恢复配置后可继续使用。

受限服务连接用于验证已提交回执重放及两种提交断连恢复。隔离 PG16 全套 257 项通过，计费回归 148 项通过、11 项跳过，计费类型检查通过。旧只读指纹单独保留。此装配位于测试支持层。目录预检先于写入事务，管理员并发 DDL 仍可能发生在两者之间，生产装配须单独处理该间隙。

## 拆集任务共同事务

以现有 `ModelTaskService.submitEpisodePlan` 为入口。隔离装配使用受限 PostgreSQL 登录，在同一连接和事务内创建真实任务、调用账本领域服务冻结一个拆集单元、插入与任务关联的 Outbox 行。任务仓储和账本仓储复用同一套 SQL。报价为隔离测试的固定 7 积分，Outbox 使用夹具表。

隔离 PG16 回归覆盖 Outbox 写入失败的整组回滚、余额不足的回滚、两个同键提交收敛至一组任务、冻结和 Outbox。真实 HTTP 路由的 BYOK 路径沿用既有装配。正式报价、生产 Outbox 与派发仍待交付。

## 拆集服务端报价与 Outbox 装配

新增可显式装配的服务端仓储。报价按工作室、配置版本、供应商及模型匹配，装配时验证并复制配置。提交服务仍使用原任务 ID 作为冻结事件 ID 和 Outbox 主键。平台报价固化到计费快照，未匹配平台报价的现有 BYOK 模型记录 exempt 快照，余额和积分流水不变。测试报价仍为 7 积分。

Outbox 迁移需在账本及 `model_tasks` 迁移之后执行。提交角色仅有指定列插入权限，RLS 要求任务和账本的工作室上下文一致。隔离 PG16 验证回滚、并发、两条计费路径和受限权限。现有 HTTP 路由尚未安装该仓储，平台凭据、上线价格和派发未启用。

## 拆集 Outbox 消费

消费者使用独立角色和固定工作室范围。用 `FOR UPDATE SKIP LOCKED` 短事务领取一条待派发记录，租约提交后调用派发端口。派发成功后凭当前有效令牌确认，过期租约可重新领取，旧令牌无法确认新租约。确认过的记录不再领取。领取租约为 10 分钟，与拆集任务的执行租约时长一致。

隔离 PG16 验证并发消费者、派发后确认前失败、同任务重领、旧令牌拒绝和角色权限。消费者提供至少一次派发，派发端仍须按原任务 ID 防重。正式工作进程和平台凭据尚未装配。

## Outbox 接入拆集执行器

内部派发器从任务仓储按工作室和任务 ID 读取拆集任务。排队任务须由可信计费责任读取端口确认为 BYOK，才进入现有拆集执行器的状态 CAS。运行中任务只进入恢复。活跃执行租约使重复派发保持未确认，过期执行租约可恢复已持久化候选或置为 EXECUTION_UNCERTAIN。终态及已暂停任务可确认，后续结果对账由现有恢复扫描继续处理。

以真实拆集执行器和计数模型夹具验证运行中重复投递、终态重放、过期恢复以及排队平台任务保持原状态。20 项拆集 API 和执行器测试通过。正式工作进程待装配，平台凭据尚未接入。

## BYOK Outbox 工作进程

生产装配增加显式 `episodeTasks.outbox.enabled` 开关，默认关闭。开启时配置同一数据库的专用受限登录，使用现有 TLS 信任配置。该登录继承 `novel_app`、`novel_billing`、`novel_episode_submission` 和 `novel_episode_outbox_consumer`，权限预检通过后才启动现有拆集 Worker。装配使用空平台报价表，HTTP 提交走 BYOK 豁免并原子创建 Outbox 项。平台凭据及扣费保持待接入。

新任务在提交事务内保存 `dispatchOwner: "outbox"`。旧队列执行扫描无论开关状态都跳过标记任务，恢复扫描仍可处理它们。开启前先升级所有旧扫描进程，避免上一版本读取标记后仍执行；已有未标记 Outbox 数据需先核对，之前的生产 HTTP 入口没有写该表。关闭开关后，已有标记任务会等待 Outbox 恢复运行。

隔离 PG16 验证专用登录、启动权限检查、任务标记和事务，29 项 API 回归通过，API、剧本和计费类型检查通过。

## BYOK Outbox 隔离 TLS 端到端验收

完整生产装配 TLS 用例通过。使用临时 PG16、独立服务登录和模拟模型传输。停掉 Worker 后经鉴权 HTTP 提交，任务保留在队列，账本固化 BYOK 豁免快照且无积分流水。仅开启旧扫描的实例扫描后任务仍排队。重新启用 Outbox 时，同键提交读回原任务，Worker 只调用模型一次，保存候选并确认 Outbox。再次重启和重放无额外调用。

过期恢复用例通过管理员构造已过期的执行及 Outbox 租约。重启后任务进入 EXECUTION_UNCERTAIN，Outbox 得到确认，模型调用数保持原值。执行不确定任务按现有规则占用执行名额。验收后清理本用例的临时任务及 Outbox 行，以便其余阶段按原配额回归。

## 拆集结算证据应用

内部应用入口读取已发布的不可变证据，复用九字段校验和账本 CAS。证据须匹配原 Outbox 拆集任务、原文和上游版本、单一计费单元、固定报价与预留额。成功证据还须匹配任务保存的候选 ID。服务端按工作室、任务、单元和证据 ID 派生稳定事件 ID。

隔离 PG16 使用合成证据验证两次并发应用得到同一回执。成功消耗 5 并释放 2，明确失败释放 7，未知保留冻结并进入待对账。缺失证据、报价错配及候选错配均被拒绝。计费回归 148 项通过、12 项跳过，API 和计费类型检查通过。
