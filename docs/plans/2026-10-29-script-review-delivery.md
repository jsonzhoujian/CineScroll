# T06-02 候选编辑与修改建议交付

日期：2026-10-29。代码基线：`fc6ee53b5d098203362137cb2c4fa3b9062e294f`。按用户要求不自动提交。

## 用户行为

已确认拆集后的剧本工作区增加“读取当前剧本”。刷新、追溯/审核模式切换后可恢复已读取的当前候选、选中元素、场次和原文位置。工作游标只保存在 URL，内容和修改状态来自服务端；切换模式不创建内容版本。

负责人和审核人可以直接编辑候选文本，成员可以提交替换内容及理由，负责人或审核人接受/拒绝建议。编辑角色的直接修改与裁决在 API 和数据库写门禁被拒绝。移动端保留读取与建议裁决，正文编辑区域仅桌面显示。

每次修改生成不可变候选版本，保留场次、转换方式、出处和失败范围。快照记录操作者、时间、动作、目标、理由、请求 ID 和命令指纹，建议保留提交人与裁决人。仍不开放正式确认、锁定或正式版本修订。

## 幂等与并发

`reviewCandidate` 为公开审核命令入口，接收 edit/suggest/decide，要求请求 ID、预期版本及理由。请求身份按工作室、项目、章节、操作者隔离；同请求同命令返回原结果，不同命令冲突。旧版本、建议目标文本改变或竞争请求推进版本均拒绝覆盖。

同方向的无效果新裁决也登记不可变结果，避免成功命令遗漏请求身份；并发请求的裁决结果不能冒充本请求结果。提交响应丢失时可按原请求查已存结果；界面不自动重复提交，未知时要求明确读取当前内容核对。

迁移 `0014_script_review.sql` 新增请求唯一索引和严格元数据约束，并限制编辑角色仅能写 suggest 审核记录。数据库索引和约束加入只读启动预检。须由可信管理员在前序迁移后应用，本轮仅操作新建隔离测试库，无业务库迁移或生产部署。

API 增加 `POST projects/:projectId/chapters/:chapterId/script-content/review`，已有只读接口返回当前用户权限；Session、no-store、净化错误及租户边界保持有效。
