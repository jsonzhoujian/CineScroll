# T07-02 设定审核交付计划

状态：in_progress。沿用T07-01四个公开边界以及已确认权限规则，不重新开放生产任务或付费调用。

本轮完成审核核心与参考仓储：负责人/审核人可编辑候选、裁决建议、确认及锁/解锁；编辑成员只能建议。正式内容不能直接编辑，接受建议派生候选，重新确认前独立正式指针保留。失败范围、空资产或未决建议阻止确认；锁定资产修改前明确解锁。

每次操作生成不可变版本，保存父版本、请求身份/指纹、目标和理由，建议保存提交/裁决身份、时间及原资产指纹。重复原请求返回原结果，改变请求内容拒绝；旧头并发保存拒绝，资产已变化时不能接受过期建议。原文引用沿用canonical校验。锁使用自有属性判断与安全写入，合法特殊编号constructor、__proto__不与对象原型混淆。

参考仓储用于确认CAS、版本与正式指针契约，不提供生产授权或事务保证。后续生产仓储须在同一事务执行角色/RLS、当前上游、转换合法性、CAS、正式指针与依赖登记，保持原生成任务结果不可变；生产适配之前不会挂载审核写入API。

实施顺序：

1. 审核核心及参考仓储（本轮）。
2. 数据库迁移、审核仓储及真实隔离库回归（第二增量完成，尚未挂载生产审核API）。
3. Session API和浏览器单项审核、明确确认/锁/解锁，以及未知操作核对。
4. 仅对明确未锁定目标局部重生，保留其他资产与证据；未知模型执行读取持久结果恢复，不重复调用。
5. 上游变化、受影响标记与公开API/Worker/仓储/浏览器整体验收。

本轮5条回归覆盖权限、证据、审计、请求重放、确认门禁、正式修订、锁、CAS、租户键隔离、过期建议、保存回执丢失恢复、上游变化及特殊资产编号。script/API类型检查通过；全套Node436项（414通过、22项条件数据库跳过），Standards/Spec复核无遗留阻断问题。未修改数据库、API/UI或生产开关，T07-02仍有必需工作，不能据本轮关闭整票。
