# T06-04 — 剧本质量报告、确认与锁定

状态：已完成。基线 `299bbc2`。不自动提交、不部署、不启用生产开关、不调用真实模型或计费。

按已确认的任务 API、Worker、候选仓储和浏览器四个公开边界执行。

1. 复用 ScriptQualityEvaluator 与原生 DeepSeek 语义适配；报告绑定精确候选、原文、已确认拆集、故事知识、上下文哈希和规则版本。
2. 复用 ModelTaskService 的持久化队列、额度、版本化模型配置、许可检查、租户隔离和未知执行恢复；独立 scriptQuality 类型避免生成任务读入质量结果。
3. 保存不可变报告，确认时只读取报告；同一事务检查当前 head、上游与报告，写入带请求标识的正式版本。锁定派生不可变正式快照，保留全部证据。
4. 页面明确评估、读取报告、确认、锁定；未知提交保留请求身份，刷新后核对，不自动重新评估。
5. 固定合成样本、边界/权限/过时与并发、隔离 PostgreSQL/TLS、浏览器闭环及完整回归；最后做 Standards 和 Spec 独立审查。

正式修订、解锁与影响范围属于 T06-05。

## 已实现

新增 [质量与正式确认契约](../contracts/SCRIPT_PUBLICATION.md)。后台质量任务固定候选/上游/规则与上下文哈希，复用工作室队列、执行额度、共享限流、BYOK 版本和许可门禁；原生语义适配仅在服务器执行。报告包含受控阻断原因与有效的逐集估算结果，先后检查候选变化后不可变保存。

确认只读取通过的精确报告；失败项、待处理建议、不完整/未知语义结果、过期报告均不能放行。仓储事务锁项目参数、原文与已确认上游及 head，数据库再验报告与内容一致性。锁定生成不可变正式后继快照，保留证据、质量来源和确认身份。操作请求、指纹、理由、操作者、时间和前后版本形成审计，响应丢失可按原请求核对。

页面支持评估、分页查找与读取报告、确认、逐元素锁定及刷新后原文追溯。旧报告提示失效，正式内容关闭候选修改入口；编辑角色不可评估、确认或锁定。URL 只保存不透明身份，未知正式操作理由仅在同标签页 sessionStorage 暂存。初次确定拒绝清除 pending；未知结果保留原请求。

迁移 `0016_script_publication.sql` 由可信管理员在前序迁移后应用，新增报告表、RLS、不可变/发布守卫、发布请求唯一索引与质量任务互斥/扫描索引，并扩展只读启动预检。本轮仅在新建隔离实例应用，未修改业务数据库。
