# 待决策事项

以下问题必须在产品规格冻结前解决。

## 市场与用户

- 第一批用户是个人动态漫创作者，还是小型短剧工作室？
- 用户当前最耗时的环节是改编、设定、分镜还是视频生成？
- 用户愿意为什么结果付费：剧本、分镜、镜头还是粗剪？
- 是否能访谈 5～10 位真实目标用户？

## 输入与改编

- MVP 最大输入是一章、若干章，还是按字数限制？
- 首版支持哪些文件格式和编码异常？
- AI 是否允许合并人物、调整事件顺序或新增转场？
- 原著还原度与影视节奏冲突时，默认优先哪一项？
- 环境、心理和世界观内容分别进入剧本、设定、旁白还是分镜？

## 输出与质量

- 首版输出偏动态漫、短剧还是通用影视剧本？
- 一章默认生成多少分钟、多少场次和多少镜头？
- 什么条件下剧本可以被标记为已确认？
- 如何衡量情节覆盖率和重要事实虚构率？
- 是否需要原文、剧本、分镜三栏联动界面？

## 视频与成本

- MVP 首个视频供应商选择 RunningHub、Seedance 直连还是其他服务？
- 平台承担模型费用，还是允许用户绑定自己的 API Key？
- 失败、超时和内容审核拒绝分别如何计费？
- 单项目、单日和单次批量生成的预算上限是多少？
- 是否只生成预览分辨率，最终定稿后再升至 4K？

## 数据与版权

- 用户是否需要声明拥有作品改编权？
- 原文和生成素材默认保存多久？
- 用户删除项目后，备份中的数据何时彻底删除？
- 平台是否承诺不使用用户作品训练模型？
- 如何处理侵权投诉、声音克隆和真人肖像？

## 产品验证

- 用哪一章小说作为固定验收样本？
- MVP 的完成标准是什么？
- 哪两个界面问题需要先用原型验证？
- 什么数据证明应该继续投入视频生成，而不是停留在剧本和分镜？

## 已做决定

- 不开发 AI 故事或小说创作工具。
- 产品只处理用户已有的小说或故事。
- 首版以一章小说的完整纵向流程为目标。
- AI 输出必须可编辑、可确认、可锁定并可追溯至原文。
