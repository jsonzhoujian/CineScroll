# 产品规格书：AI 小说动态漫改编工作台

状态：v0.1 草案，基于已确认需求和低保真原型整理，尚未进入正式开发。

日期：2026-09-21

## 1. 产品定义

本产品面向中国大陆 1～10 人的 AI 动态漫/漫剧工作室，将用户拥有合法改编权的小说章节转换为可编辑、可确认、可追溯的故事知识、动态漫剧本、文字设定和完整分镜。

产品不替代作者创作小说，也不在 MVP 中生成图片、音频、视频或最终成片。

## 2. MVP 成功结果

用户应能在一个项目中完成以下闭环：

1. 通过粘贴、TXT 或 DOCX 导入一章不超过 20,000 字的原文。
2. 审核 AI 提取的故事知识及不确定项。
3. 选择单集时长、画面比例和叙事形式，确认拆集建议。
4. 逐阶段确认剧本、设定和分镜。
5. 在任一改编结果上查看原文依据和转换方式。
6. 将已确认结果导出为 DOCX、XLSX 和完整 JSON。

验证成功标准：至少 5 家封闭内测工作室完成完整流程，其中至少 3 家在 14 天内处理第二个项目或章节并表达付费意愿。

## 3. 用户角色与权限

| 能力 | 负责人 | 编辑 | 审核人 |
| --- | --- | --- | --- |
| 创建和删除项目 | 是 | 否 | 否 |
| 邀请与管理成员 | 是 | 否 | 否 |
| 编辑未确认候选内容 | 是 | 是 | 是 |
| 对已确认内容提交修改建议 | 是 | 是 | 是 |
| 接受或拒绝修改建议 | 是 | 否 | 是 |
| 确认阶段结果 | 是 | 否 | 是 |
| 锁定内容 | 是 | 否 | 是 |
| 导出已确认结果 | 是 | 是 | 是 |
| 查看审计记录 | 是 | 否 | 是 |

MVP 不支持多人同时编辑；成员对已确认内容只能提交修改建议，不能直接覆盖正式版本。

## 4. 核心对象

```text
工作室
└── 项目（作品）
    ├── 项目成员
    ├── 原文文件
    │   └── 章节
    │       └── 原文版本
    │           └── 原文片段
    ├── 故事知识条目
    ├── 拆集方案
    │   └── 集
    │       └── 场次
    │           └── 剧本元素
    ├── 设定资产
    ├── 分镜
    │   └── 镜头
    ├── 改编映射
    ├── 修改建议
    ├── 内容版本
    └── AI 任务与积分流水
```

所有 AI 输出先成为候选内容；只有经负责人或审核人确认后，才成为下游阶段可以依赖的正式内容。

## 5. 信息架构

### 5.1 一级页面

- 登录：手机验证码、微信扫码、账号绑定。
- 项目列表：创建项目、查看状态、进入项目、回收站。
- 项目创建：作品信息、改编权声明、画面比例、默认叙事形式。
- 章节管理：上传、章节识别、选择本次处理章节、原文版本差异。
- 核心工作台：故事知识、剧本、设定和分镜四阶段工作。
- 任务中心：进度、成功范围、失败范围、局部重试和积分结算。
- 通知中心：任务完成、审核请求、建议处理和异常通知。
- 成员与权限：邀请、角色设置和成员状态。
- 计费中心：套餐、积分、冻结与退回记录、BYOK。
- 项目设置：删除、恢复、导出、审计记录和版权状态。

### 5.2 移动端

移动端仅提供任务进度、阶段审核、建议接受/拒绝和通知，不承担完整内容编辑。

## 6. 核心工作台

### 6.1 四阶段导航

工作台始终展示故事知识、剧本、设定、分镜四个阶段。用户可以查看已有阶段；上一步未确认时，不能生成下一阶段正式内容。

每个阶段显示以下状态之一：

- 未开始
- AI 生成中
- 生成部分成功
- 待审核
- 有待确认问题
- 已确认
- 有上游变更影响
- 已锁定
- 合规受限

### 6.2 三种工作模式

桌面端保留三种可自由切换的工作模式：

| 模式 | 主要任务 | 核心布局 |
| --- | --- | --- |
| 追溯模式 | 核对原文与改编关系 | 原文、改编内容、追溯检查器三栏 |
| 审核模式 | 处理建议并确认阶段 | 阶段导航、内容对照、审核操作区 |
| 分镜模式 | 逐镜检查和编辑 | 镜头列表、镜头详情、原文依据 |

三种模式不是三份数据。切换模式必须保留项目、章节、集、场次、镜头、原文定位、选中内容、阶段状态、确认结果和建议处理状态。

系统可以根据当前阶段推荐进入某种模式，但用户始终可以自由切换。URL 可以记录工作模式和当前定位，以便刷新或分享内部链接；模式参数不得成为内容版本的一部分。

### 6.3 共同操作

- 查看来源原文与转换方式。
- 编辑未确认候选内容。
- 提交或处理修改建议。
- 接受、拒绝、锁定或局部重新生成。
- 查看上游变化产生的受影响项。
- 查看当前版本、历史版本与操作者。

## 7. 关键用户流程

### 7.1 导入与章节选择

1. 用户选择粘贴文本、TXT 或 DOCX。
2. 系统执行格式、字数、合规和章节结构检查。
3. 多章节文件展示识别目录，用户选择本次处理的一章。
4. 用户确认合法改编权声明。
5. 系统保存原始文件、章节和不可静默覆盖的原文版本。
6. 系统为原文段落建立稳定标识并创建解析任务。

异常：超过 20,000 字时不直接截断，要求用户选择或拆分章节；部分解析失败时保留成功结果并允许局部重试。

### 7.2 故事知识确认

1. 系统提取人物、关系、事件、场景、道具和世界规则。
2. 每条知识展示原文证据，并区分原文明示与 AI 推断。
3. 人物别名、隐藏身份或冲突事实进入待确认队列。
4. 用户逐项接受、修订、拒绝或锁定。
5. 负责人或审核人确认本阶段。

### 7.3 拆集与剧本

1. 用户选择 1、3 或 5 分钟，9:16 或 16:9，以及旁白型或对白型。
2. AI 建议一集或多集，并展示每集覆盖原文范围和核心事件。
3. 用户确认拆集方案与重大改编建议。
4. AI 生成结构化动态漫剧本。
5. 环境和心理描写分别转换为环境镜头、动作、声音或旁白，并记录转换方式。
6. 用户在追溯或审核模式中修订并确认剧本。

### 7.4 设定与分镜

1. 系统基于已确认剧本生成角色、场景、道具和全局画风文字设定。
2. 用户修订、确认并锁定设定资产。
3. 系统根据视觉焦点、动作、情绪和信息变化拆分镜头。
4. 每个镜头包含画面、动作、对白/旁白、时长、景别、机位、运镜、声音、情绪和资产引用。
5. 用户在分镜模式中逐镜审核，确保总时长误差不超过 10%。
6. 负责人或审核人确认完整分镜。

### 7.5 上游变更

1. 用户修改已确认内容或重新导入章节。
2. 系统创建新版本并计算差异。
3. 下游相关内容被标记为受影响项，但不会自动覆盖或重做。
4. 用户选择保留、修订或局部重新生成哪些项目。
5. 已锁定内容始终需要用户明确解锁后才能被替换。

## 8. AI 任务规格

每个 AI 阶段使用结构化输入和结构化输出，并执行字段、引用、范围与业务规则校验。长任务在后台运行，页面展示阶段进度、完成范围和失败范围。

AI 任务必须满足：

- 任务提交前显示固定或预估积分并冻结对应额度。
- 按成功完成部分结算，失败部分自动退回。
- 一章不超过 20,000 字时，每个阶段通常在 5 分钟内返回。
- 局部失败不清除成功结果。
- 重试只覆盖用户选择的失败项。
- BYOK 调用不消耗对应模型积分，但仍受高级订阅、合规扫描和审计约束。

## 9. 追溯、版本与审计

每条故事知识、对白、动作和镜头至少满足以下一种情况：

- 关联一个或多个原文片段；
- 明确标记为经用户批准的改编新增。

改编映射记录来源、目标、转换类型、创建方式和确认状态。关键操作记录操作者、时间、对象、操作前后版本及原因。

需审计的操作包括导入、修改建议、接受/拒绝、确认、锁定、重新生成、导出和删除。

## 10. 导出契约

- DOCX：项目说明、拆集大纲、已确认剧本、角色/场景/道具设定和全局画风。
- XLSX：每集一个分镜工作表，包含镜头全部字段和追溯标识。
- JSON：保存全部结构化数据、版本、状态、资产引用和追溯关系，字段版本号必须明确。

默认仅导出已确认内容；若允许导出候选内容，文件必须醒目标注“未确认”。

## 11. 非功能与合规要求

- 中国大陆用户作品默认存储在中国大陆区域。
- 用户内容默认不用于平台或第三方模型训练。
- 调用可能使作品数据离境的模型前，必须明确告知并取得必要授权。
- 删除项目后进入 30 天回收站；到期删除业务数据和对象文件，备份最长 90 天自然过期。
- 合规限制、版权投诉和普通技术失败使用不同状态与提示。
- 收到有效版权投诉时暂停相关项目生成和分享，但不静默删除项目。

## 12. MVP 验收场景

1. 用户导入包含多个章节的 DOCX，选择一章后成功解析，其余章节保留待处理。
2. 同一人物的两个称谓无法确定时，系统展示两侧证据并等待用户确认，不自动合并。
3. 用户从追溯模式切换到审核模式再切换到分镜模式，当前场次、镜头、原文定位和确认状态保持一致。
4. 用户修改已确认剧本后，相关设定和镜头被标记为受影响，锁定项不被覆盖。
5. AI 分镜任务部分失败，成功镜头保留，失败镜头可单独重试且积分自动退回。
6. 导出的 DOCX、XLSX 和 JSON 内容一致，随机抽取的对白、动作和镜头均能追溯至原文或批准的改编新增。
7. 回归样本核心事件覆盖率不低于 90%，无未经批准的核心事实变更，单集时长偏差不超过 10%。

## 13. 暂不进入开发的待决策项

- 各套餐成员数、月度积分和价格。
- 1、3、5 分钟成片对应的推荐场次数与镜头数区间。
- 质量评分的具体计算方法、人工评分表和回归阈值。
- 手机号与微信重复账号合并规则。
- BYOK 支持的供应商、密钥托管方式和数据离境提示。
- 版权申诉材料、处理时限和恢复规则。

## 14. 下一阶段出口条件

进入任务拆分或正式开发前，至少需要完成：

1. 通过公开一手资料研究确认行业问题、生产约束和合规边界，并明确证据不能证明的范围。
2. 完成低保真原型内部探索测试，记录状态矛盾及正式实现测试需求。
3. 确认 MVP 页面清单、权限矩阵和核心对象关系。
4. 定义 JSON 导出契约与 AI 各阶段结构化输出 Schema。
5. 为玄幻、都市、悬疑各准备至少一份合法回归样本或结构化测试夹具。
6. 对待决策项明确哪些属于内测前必须确认，哪些可以通过内测验证。

目标工作室测试后移至可操作 MVP／封闭内测阶段，作为扩大内测和收费上线的门禁，不再阻塞可逆的架构设计。
