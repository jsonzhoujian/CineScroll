# ADR-0003：中国大陆单区域数据与对象存储

## 状态

Proposed

## 背景

首发面向中国大陆，用户上传可能受版权保护的作品。产品要求默认不训练、数据区域透明、删除可追踪，并支持 DOCX/TXT 原文件和 DOCX/XLSX/JSON 导出。内测阶段没有跨区域高可用需求，也不应默认将作品发送至境外服务。

## 决策

- 生产数据默认部署在一个中国大陆云区域。
- PostgreSQL 保存业务元数据、正文片段、版本关系和审计索引。
- 私有对象存储保存原文件、导出物和临时制品，通过 `StoragePort` 隔离 OSS/COS 差异。
- 对象只通过短期签名 URL 访问，key 不包含用户文件名或可猜测租户标识。
- 数据库、对象存储和备份启用静态加密；传输使用 TLS。
- 删除采用 30 天回收站，期满删除业务数据和对象，备份最长 90 天自然过期。
- 使用可能离开中国大陆的数据处理服务前，执行任务级告知、授权和审计。
- 日志、指标和追踪禁止记录原文正文、授权材料正文、验证码和密钥。

## 后果

### 正面

- 与产品的数据区域承诺一致。
- 关系数据和大文件职责清晰，导出物可独立设置生命周期。
- 云厂商可通过端口替换，不让对象存储 SDK 进入领域层。

### 负面

- 大陆云资源、备案、域名、短信和微信接入需要额外运营准备。
- 单区域灾难可能超过 4 小时 RTO；MVP 接受该风险。
- 跨境模型可用性受限，需要大陆替代模型或拒绝任务。

## 备选方案

- **境外统一部署**：与默认大陆存储目标冲突，拒绝。
- **多云双写**：成本和一致性复杂度过高，MVP 不采用。
- **正文和文件全部放对象存储**：会增加片段查询、版本事务和追溯复杂度，暂不采用。
- **正文使用 MongoDB**：当前关系、事务和引用完整性更重要，PostgreSQL 足够。

## 复核触发条件

- 需要跨区域容灾或境外市场。
- 项目正文与版本规模使 PostgreSQL 存储/查询成为证实的瓶颈。
- 法规、云服务资质或备份要求变化。
