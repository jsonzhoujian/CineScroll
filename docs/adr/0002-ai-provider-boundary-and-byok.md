# ADR-0002：AI Provider Adapter、结构化契约与 BYOK 边界

## 状态

Proposed

## 背景

故事知识、剧本、设定和分镜可能使用不同模型。供应商的上下文长度、批量大小、输入格式、地域、成本、限流和结构化输出能力会变化。高级工作室还需要绑定自己的 API Key。若领域对象直接携带供应商字段，切换模型、重试和审计都会变得不可控。

## 决策

- 定义供应商无关的 `ProviderPort`：capabilities、estimate、submit/poll/cancel、normalizeError 和 usage。
- 每个阶段拥有版本化 Request/Response JSON Schema。
- Orchestrator 生成不可变的 canonical input snapshot；Adapter 将其映射为供应商请求。
- 输出先进入隔离区，通过 Schema 和领域不变量后才产生候选内容版本。
- 条目级结果支持 success/failure；只重试失败 scope。
- 任务幂等键为 `jobId + scopeKey`，供应商请求 ID 只作外部关联。
- BYOK 密钥使用大陆云 KMS 信封加密，数据库不存明文；仅 Worker 在调用窗口解密。
- 平台密钥与 BYOK 使用相同 Adapter，但分别记录成本责任和积分规则。
- 数据可能离开大陆前执行模型地域策略和用户授权检查。

## 后果

### 正面

- 领域和版本模型不绑定 Seedance、可灵或文本模型厂商。
- 可针对任务、成本、地域和质量逐步调整路由。
- 结构校验、局部失败、幂等和审计行为一致。
- BYOK 不需要把密钥暴露给 Web 客户端。

### 负面

- 需要维护多套 Adapter 和供应商契约测试。
- canonical schema 与供应商能力不完全匹配时需要降级、拆批或拒绝。
- 自动路由的质量评价在缺少真实数据前只能保持保守。

## 备选方案

- **每个阶段直接调用一个固定模型**：开发快，但会把模型限制泄漏到领域和 UI，拒绝。
- **让用户每次选择模型**：增加认知负担且难以保证质量，作为高级设置后移。
- **在浏览器直接调用 BYOK**：密钥泄露、审计和跨域风险不可接受。
- **输出自由文本再人工解析**：不可可靠重试与追溯，拒绝作为正式管线。

## 复核触发条件

- 有足够质量与成本数据支持自动路由。
- 供应商提供大陆数据区、异步回调或批量接口的新能力。
- BYOK 合规和密钥托管要求变化。
