# 需求草案：AI 小说动态漫改编工作台

状态：需求基线 v0.1 已确认，低保真原型已完成第一轮决策，等待目标用户验证。标记为“待定”的内容不得视为实现承诺。

确认日期：2026-09-21

## 1. 产品目标

帮助中国大陆 1～10 人的小型动态漫/漫剧工作室，把已有小说章节转化为可编辑、可确认、可追溯的剧本、设定与完整分镜。

MVP 不负责原创小说，也不生成图片、音频或视频。

## 2. 核心用户

- 工作室负责人：创建项目、邀请成员、确认重要改编和最终输出。
- 编剧/改编人员：审核故事知识、编辑剧本和处理原文映射。
- 分镜人员：审核设定与分镜，导出后续生产资料。

MVP 不支持多人同时编辑同一内容。

## 2.1 账号与市场

- 首发市场为中国大陆。
- 用户可以使用手机验证码或微信扫码登录。
- 同一用户可以将手机号和微信身份绑定到同一账号。

## 3. 核心流程

```text
创建项目
→ 导入一章小说
→ 解析原文与故事知识
→ 用户确认故事知识
→ 用户选择目标单集时长、画面比例与叙事形式
→ AI 建议集数与剧情切分
→ 用户确认拆集方案
→ 生成并确认剧本
→ 生成并确认角色/场景/道具设定
→ 生成并确认完整分镜
→ 导出剧本、设定与分镜
```

任何阶段未确认时，不得自动生成下一阶段的正式内容。

## 4. 功能需求

### 4.1 项目与成员

- FR-001：一个项目代表一部作品；用户可以创建、查看和管理改编项目。
- FR-001a：用户可以在同一项目中逐章导入和处理原文，但 MVP 每次最多处理一章。
- FR-002：项目负责人可以邀请成员加入项目。
- FR-003：成员不得直接覆盖正式内容；编辑通过修改建议提出变更，由负责人或审核人处理。
- FR-004：系统必须记录内容的创建者、修改者和确认者。
- FR-005：成员对已确认内容提交修改建议，而不是直接覆盖正式版本。
- FR-006：项目负责人可以接受或拒绝成员的修改建议。
- FR-007：项目角色包括负责人、编辑和审核人。
- FR-008：负责人管理项目与成员，编辑创建修改建议，审核人确认阶段结果；具体权限矩阵待细化。
- FR-008a：负责人和审核人可以确认故事知识、剧本、设定和分镜。
- FR-008b：修改建议必须包含建议替换内容和修改理由。
- FR-008c：负责人或审核人可以接受或拒绝修改建议，并记录处理结果。

### 4.1a 账号

- FR-009：系统支持中国大陆手机号验证码登录。
- FR-009a：系统支持微信扫码登录。
- FR-009b：系统支持将手机号与微信身份绑定到同一账号，并处理重复账号合并；具体规则待定。

### 4.2 原文导入

- FR-010：用户可以粘贴文本导入原文。
- FR-011：用户可以上传 TXT 文件。
- FR-012：用户可以上传 DOCX 文件。
- FR-013：MVP 单次输入为一章，最多约 20,000 个中文字符。
- FR-014：系统必须保留不可被 AI 静默覆盖的原文版本。
- FR-015：系统必须为原文段落分配稳定位置标识。
- FR-016：用户重新导入已存在章节时，系统必须创建新的原文版本而非覆盖旧版本。
- FR-017：系统必须显示新旧原文差异，并标记受影响的故事知识、剧本、设定和分镜。
- FR-018：文件包含多个章节时，系统识别章节目录并允许用户选择本次处理的一章。
- FR-019：同一文件中的其余章节保存在项目中，等待用户后续逐章处理。

### 4.3 故事知识

- FR-020：系统从原文提取人物、关系、场景、道具、事件和世界规则。
- FR-021：每条故事知识必须关联一个或多个原文段落。
- FR-022：AI 推断必须与原文明示事实区分。
- FR-023：用户可以修改、接受、拒绝和锁定故事知识。
- FR-024：故事知识经用户确认后才能成为下游生成依据。
- FR-025：人物别名或隐藏身份无法确定时，系统必须保持候选关系并展示双方原文证据，由用户确认是否合并。
- FR-026：冲突事实必须并列保存及展示出处，由用户标记为设定变化、人物误解、作者矛盾或其他情况。

### 4.4 拆集与改编

- FR-030：用户设置目标单集时长。
- FR-030a：MVP 提供 1、3、5 分钟三个目标时长预设。
- FR-030b：用户在项目创建时选择 9:16 竖屏或 16:9 横屏。
- FR-030c：用户在生成前选择旁白型或对白型叙事。
- FR-031：系统根据剧情密度建议将一章拆为一集或多集。
- FR-032：拆集建议必须展示每集覆盖的原文范围与核心事件。
- FR-033：用户可以调整并确认拆集方案。
- FR-034：默认允许压缩文学描述和合并场次，但不得改变核心故事事实。
- FR-035：合并人物、删除重要事件或重排事件必须作为重大改编建议单独展示。
- FR-036：重大改编未获用户明确批准时不得进入正式剧本。

### 4.5 剧本

- FR-040：系统根据已确认故事知识和拆集方案生成可编辑剧本。
- FR-041：剧本采用动态漫结构化格式，包含场次标题、环境、人物、动作、对白、旁白和声音。
- FR-041a：旁白型优先保留叙述信息，对白型优先将叙述转换为可见行动与角色表达。
- FR-041b：环境和心理描写必须分类转换为环境镜头、动作表演、声音或旁白，并记录转换方式。
- FR-042：每段对白和动作必须关联来源原文段落。
- FR-043：没有直接原文依据的内容必须标记为“改编新增”。
- FR-044：用户可以编辑、接受、拒绝、重新生成和锁定局部剧本内容。
- FR-045：剧本经用户确认后才能生成正式设定。

### 4.6 设定

- FR-050：系统基于已确认内容生成可供分镜使用的角色、场景和道具文字设定卡。
- FR-050a：设定卡必须包含可见特征、状态变化和在分镜中的使用限制。
- FR-050b：角色设定卡包含姓名/称谓、身份、年龄、体型、发型、服装、标志物、性格外显方式、表情习惯、动作习惯、当前状态、状态变化和禁止表现。
- FR-050c：场景设定卡包含名称、空间结构、时代、天气、光线和色调。
- FR-050d：道具设定卡包含名称、外观、材质、尺寸、持有人和剧情作用。
- FR-051：每项设定必须显示来源原文和改编依据。
- FR-052：用户可以编辑、确认和锁定设定。
- FR-053：设定经用户确认后才能生成正式分镜。
- FR-054：系统提供全局画风预设，用户可以编辑其文字定义。
- FR-054a：全局画风作为分镜描述的约束，但 MVP 不包含参考图或模型参数。
- FR-055：MVP 不生成角色图、场景图、道具图或三视图。

### 4.7 分镜

- FR-060：系统根据已确认剧本和设定生成完整分镜。
- FR-060a：系统根据视觉焦点、人物动作、情绪和信息变化拆分镜头，不按固定秒数或单句对白机械拆分。
- FR-060b：系统必须记录每个镜头的拆分依据。
- FR-061：每个分镜必须关联对应剧本内容和来源原文。
- FR-062：分镜必须包含画面、人物、动作、对白/旁白、预计时长、景别、机位、运镜、声音、情绪和设定资产引用。
- FR-063：MVP 分镜不绑定特定图片或视频模型，也不承诺输出最终模型提示词。
- FR-064：用户可以编辑、确认、锁定和局部重新生成分镜。

### 4.8 版本与影响

- FR-070：系统必须保存原文、故事知识、剧本、设定和分镜的版本历史。
- FR-071：修改已确认的上游内容时，系统必须标记可能失效的下游内容。
- FR-072：系统不得因上游修改而自动覆盖已锁定内容。
- FR-073：修改已确认内容必须创建新版本并显示影响范围。
- FR-074：用户选择需要重新生成的受影响项；系统不得自动批量重新生成。
- FR-075：用户可以局部重新生成单条故事知识、单个场次、单项设定或单个分镜。
- FR-076：局部重新生成不得覆盖不在所选范围内的内容或任何已锁定内容。

### 4.9 任务恢复

- FR-077：AI 任务部分失败时，系统必须保存所有已成功完成且通过格式校验的结果。
- FR-078：系统必须清楚标记失败范围和失败原因。
- FR-079：用户可以只重试失败部分，不必重新执行整个章节。

### 4.10 导出

- FR-080：用户可以将项目说明、拆集大纲、已确认剧本和设定导出为 DOCX。
- FR-081：DOCX 中的设定包含角色、场景、道具和全局画风文字定义。
- FR-082：用户可以将完整分镜导出为 XLSX，并按集建立工作表。
- FR-083：用户可以导出包含剧本、设定、分镜及追溯关系的完整 JSON 数据。
- FR-084：普通文档编辑和导出不额外消耗 AI 积分。

### 4.11 异步任务与通知

- FR-090：AI 解析和生成任务必须在后台运行，用户关闭页面后任务继续执行。
- FR-091：系统显示任务当前阶段、进度、已完成范围和失败范围。
- FR-092：任务完成或需要用户处理时发送站内通知。
- FR-093：对于不超过 20,000 字的一章内容，每个 AI 阶段通常应在 5 分钟内返回；超时不等同于自动失败。

### 4.12 版权、隐私与删除

- FR-100：上传作品前，用户必须声明其拥有作品或合法改编权，系统保存声明记录。
- FR-101：用户作品默认不得用于平台或第三方模型训练。
- FR-102：训练授权必须独立于服务条款、由用户主动选择并可撤回。
- FR-103：删除项目后，项目进入 30 天回收站。
- FR-104：回收期结束后，系统删除业务数据库中的项目数据和对象存储文件。
- FR-105：备份数据按公开周期自然过期，项目彻底删除后最长保留 90 天。
- FR-106：中国大陆用户作品默认存储在中国大陆区域。
- FR-107：项目彻底删除后，备份中的相关数据最长保留 90 天并随备份周期覆盖。
- FR-108：调用可能导致作品数据离开中国大陆的模型前，系统必须明确告知用户相关范围并取得必要授权。

### 4.13 订阅、积分与模型

- FR-110：收费采用月度订阅包含使用额度，超出部分消耗 AI 积分。
- FR-110a：首版提供免费试用、工作室版和高级工作室版三个套餐层级。
- FR-110b：免费试用最多处理 3,000 字，并允许体验受额度限制的剧本、设定和分镜生成。
- FR-110c：工作室版和高级工作室版按成员数量和每月 AI 积分区分；具体额度与价格待验证。
- FR-111：系统为每项 AI 任务展示固定或预估积分，后台记录实际模型调用成本。
- FR-111a：任务提交时冻结预计积分，按成功完成的部分结算，并自动退回失败部分对应积分。
- FR-112：平台默认根据任务自动选择文本模型。
- FR-113：高级版用户可以绑定自己的模型 API Key；密钥权限、加密与支持范围待定。
- FR-114：使用自有 API Key 仍要求高级订阅，但对应模型调用不消耗平台 AI 积分。

### 4.14 合规、投诉与审计

- FR-120：上传内容必须经过自动合规扫描。
- FR-121：系统对禁止执行的 AI 任务说明原因，并提供申诉入口。
- FR-122：系统不得因自动扫描结果静默删除整个项目。
- FR-123：收到有效版权投诉后，系统暂停相关项目的 AI 生成和对外分享。
- FR-124：系统通知用户提交授权证明，并根据处理结果恢复或下架相关内容。
- FR-125：系统记录导入、修改建议、确认、锁定、重新生成、导出和删除等关键操作。
- FR-126：负责人可以查看所属项目的关键操作审计记录。

### 4.15 工作台与移动端

- FR-130：用户可以查看故事知识、剧本、设定和分镜全部阶段。
- FR-131：上一步未确认时，系统不得生成下一阶段正式内容。
- FR-132：原文追溯界面采用左侧原文、右侧剧本或分镜的双栏布局。
- FR-133：点击任一改编内容时，系统高亮其来源原文；点击原文时显示相关改编内容。
- FR-134：分镜编辑界面采用左侧镜头列表/表格和右侧当前镜头详情布局。
- FR-135：移动端支持查看任务进度、审核阶段结果、接受或拒绝修改建议以及接收站内通知。
- FR-136：MVP 移动端不要求支持完整剧本、设定或分镜编辑。
- FR-137：桌面工作台提供追溯、审核和分镜三种工作模式，用户可以在同一项目中自由切换。
- FR-138：三种工作模式必须使用同一份项目数据，不得为切换模式复制剧本、设定、分镜或修改建议。
- FR-139：切换工作模式时必须保留当前章节、集、场次、镜头、原文定位、阶段确认和建议处理状态。
- FR-140：工作模式只决定信息布局与操作重点，不改变四阶段工作流、权限和确认门禁。
- FR-141：系统可以按当前阶段推荐工作模式，但不得阻止用户切换到其他模式。

## 5. 业务规则

- BR-001：原文是改编事实的最终证据，除非用户明确批准改编新增内容。
- BR-002：AI 输出默认是候选内容，不自动成为正式内容。
- BR-003：每一阶段必须确认后才能驱动下一阶段。
- BR-004：锁定内容不得被批量生成或重新生成覆盖。
- BR-005：重大改编必须可解释、可拒绝且可追溯。
- BR-006：一章可以拆成多集，但一集不得无来源地引入后续章节事实。
- BR-007：成员修改以建议形式提交，只有获授权的负责人可以使其成为正式版本。
- BR-008：分镜预计时长总和与目标单集时长的偏差不得超过 10%。
- BR-009：人物别名、隐藏身份和冲突事实不得由 AI 在缺少用户确认时自动合并或覆盖。
- BR-010：同一项目的后续章节可以更新人物状态和世界认知，但不得静默改写历史版本。
- BR-011：用户未主动授权时，其原文、知识库、剧本、设定和分镜不得用于训练。
- BR-012：回收站中的项目不可参与新的 AI 任务，恢复后可继续使用。
- BR-013：失败任务不得要求用户人工申请积分退回。
- BR-014：合规限制和版权投诉必须与普通技术失败使用不同状态和提示。
- BR-015：追溯、审核和分镜是同一份正式内容的三种视图，不是三个独立版本；任何模式中的正式修改必须在其他模式中立即可见。

## 6. 质量验收基线

- QR-001：核心事件覆盖率不低于 90%。
- QR-002：不得虚构或改变未经批准的核心事实。
- QR-003：对白、动作和分镜均可追溯至原文，或明确标记为改编新增。
- QR-004：单集全部镜头预计时长总和与目标时长偏差不超过 10%。
- QR-005：验收指标必须通过固定样本文本执行回归评估；样本和评分方式待定。
- QR-006：不超过 20,000 字的一章内容，每个 AI 阶段的通常响应目标为 5 分钟以内。
- QR-007：固定回归样本必须覆盖玄幻、都市和悬疑三类授权或自有文本。

## 7. MVP 范围外

- AI 故事或小说原创、续写与发布
- EPUB、PDF 和网页抓取
- 图片、音频和视频生成
- 自动粗剪和 4K 输出
- 自由节点画布
- 多人实时共同编辑
- 专业剪辑时间线
- 整本小说一次自动处理
- 自建模型或 GPU 集群

## 9. 发布与验证

- LR-001：首发采用封闭内测，邀请 5～10 家目标工作室。
- LR-002：至少 5 家工作室完成从导入到导出的完整流程。
- LR-003：至少 3 家工作室在首次使用后的 14 天内处理第二个项目或章节。
- LR-004：上述复用工作室明确表达付费意愿，才视为产品方向得到初步验证。
- LR-005：公开发布前必须根据内测结果复核改编质量、阶段耗时、AI 成本和套餐额度。

## 10. 下一阶段

需求基线确认后，先制作低保真交互原型，重点验证：

1. 原文与剧本/分镜双栏追溯是否清晰。
2. 故事知识、剧本、设定和分镜的阶段确认是否顺畅。
3. 左侧镜头列表/表格与右侧镜头详情是否支持高效审核。
4. 追溯、审核和分镜三种工作模式能否自由切换，并保持上下文和数据一致。

原型决策：三个方案全部保留，分别作为“追溯模式”“审核模式”和“分镜模式”，不再从中选择单一主工作台。

原型未经目标工作室验证、产品规格出口条件未满足前，不进入正式代码实现。下一份主文档为 [产品规格书](./PRODUCT_SPEC.md)。
