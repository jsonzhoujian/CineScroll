## What to build

逐镜审核确认分镜并执行时长与权限门禁。

## Acceptance criteria

- [x] 统一编辑仅建议、负责人/审核人编辑候选与裁决，正式修改派生候选，锁定先解锁。
- [x] 逐集总时长与目标偏差不超过10%，失败、缺项、待决建议或旧上游阻止确认。
- [x] 资产/剧本/原文引用、正式指针、版本审计和局部重生保持一致。
- [x] 三模式游标和确认状态一致，移动端写限制遵循既有工作台规则，浏览器和实库负向回归通过。

## Context and boundaries

权威输入：docs/PRODUCT_SPEC.md（权限、7.4、7.5、8与MVP验收）、CONTEXT.md、docs/contracts/DOMAIN_MODEL.md、settings/storyboard canonical Schema；复用T06交付的正式读取、不可变版本、角色规则、后台任务、许可与未知执行恢复。参见docs/plans/2026-11-03-t06-final-acceptance.md。不得把历史读取当生成授权，不得重复建设已经具备的基础设施。

本票为纵向交付：按已确认公共API、Worker、仓储与浏览器测试边界验证并独立审查。用户要求每轮提供Git提交文案、不自动提交。不部署、不自动调用真实付费模型、不启用真实计费。依赖中完成的前置不应被反向重新设为阻塞。

## 实施进度

- 已接通创建者明确提交审核。提交基于已完成的私有候选，重复提交返回同一审核编号。项目成员从独立列表查阅已提交候选及证据。任务记录和其他生成或重试候选仍由原创建者读取。提交过期候选后仍可历史查阅，正式确认时需复验上游。
- 已接镜头画面与时长的审核。编辑提交建议，负责人和审核人可直接修改或接受、拒绝建议。操作按审核编号追加并记录版本、操作者和理由。旧候选保留，过期建议不能覆盖后续修改。
- 已接镜头锁定、解锁和正式确认。按照章节选出最新确认的修订，后续内容修改作为待确认修订。另一个候选替换正式版本前须先解锁当前正式镜头。上游变更后仍允许负责人或审核人对当前正式版本解锁，历史镜头内容仍可只读追溯。
- PostgreSQL 在确认事务内复验当前上游、版本、缺失集场、失败项、待决建议和每集 ±10% 时长范围。工作台显示各集的实际和目标时长。
- 2026-11-17 验收完成。隔离 TLS 用例在正式确认后执行私有局部重试，验证保留成功镜头的资产、剧本和原文引用，且正式快照、审核名单及确认审计记录不变。
- Chromium 验证从分镜切到追溯时定位原文，切到审核时按版本读取关联的正式剧本，即使另有活动草稿。返回分镜保留所选镜头。移动端可读证据，写入控件隐藏。T07-05 已解锁。
