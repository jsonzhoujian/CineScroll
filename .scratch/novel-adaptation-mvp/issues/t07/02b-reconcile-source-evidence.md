# T07-02b — 跨源依据迁移与人工修订闭环

**What to build:** 重新导入章节后，负责人/审核人明确处理旧设定依据：对未锁定资产的相同片段作受控引用迁移，对变化/缺失依据人工重新追溯和修订，分批形成可重新确认的候选；保留旧正式版和旧证据。

**Blocked by:** T07-02a — 复用核对候选、有效/待核对项、幂等审计和重新确认门禁。

**Status:** ready-for-agent（T07-02a已完成，可开始）

## Accepted rules

- 引用迁移仅在逐项明确保留后，由服务器核验每个片段的新旧归属、身份、完整哈希及全文，不能仅比较截短ID。
- 同文本/同ID不证明上下文语义适用，不能自动作保留决定；重复段落及改序不能跳过核对。
- 原文版本身份变化属于依据变化，锁定资产必须先明确解锁，不因片段相同形成例外。
- 变化、缺失或未授权依据进入待核对；不作为新上游有效资产，禁止确认。旧建议只读留旧版本。

## Acceptance criteria

- [ ] 通过Session、界面及真实事务仓储完成明确迁移、明确解锁、人工选择当前授权片段、修改内容和重新确认。
- [ ] 人工修订也覆盖原文版本未变化、但不适合原样保留的待核对目标，不要求用户先作出不真实的保留决定。
- [ ] 同文重复导入可经明确选择迁移；重复段落/改序、片段变化/缺失、哈希或全文不匹配均不能静默迁移。
- [ ] 伪造片段、跨章节/租户引用及把旧引用直接改为新版本身份被拒绝；所有有效资产符合当前证据校验。
- [ ] 锁沿用/解锁和旧依据历史保持可追溯，未处理及待核对项阻止整候选确认，正式指针保持至明确确认。
- [ ] 上游再次变化、并发处理和原请求重放安全；处理结果、证据、真实依赖和指针事务一致，失败回滚。
- [ ] 公开API/仓储/浏览器覆盖迁移与人工修订闭环，临时PG/TLS验证隔离和重启；类型检查与独立双轴复核通过。

## Scope

不自动改写事实、不凭相同片段自动确认、不实现AI重生；不部署、不启用生产、不自动提交。每次交付给出Git提交文案。
