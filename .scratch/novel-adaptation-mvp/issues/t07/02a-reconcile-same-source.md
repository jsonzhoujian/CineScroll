# T07-02a — 同源跨上游分批核对与原样保留

**What to build:** 原文版本不变、正式剧本等上游变化后，负责人/审核人可在页面开始跨上游核对，逐项明确原样保留设定，分批形成候选，全部处理并重新确认后才推进正式指针。旧正式版本始终可追溯。

**Blocked by:** None — can start immediately；Q1–Q4规则与四项拆分已由用户确认。

**Status:** ready-for-agent

## Accepted rules

- 原样保留要求资产内容及原文依据完全不变，可沿用原锁及锁审计；任何内容/依据变化先明确解锁。
- 未处理资产及依据待核对项仅作历史展示，不属于新上游有效资产，阻止整个候选确认。
- 旧建议原状态留在旧版本，不自动迁移、采纳或拒绝；新上游需要的建议重新提交。
- 负责人/审核人作处理决定，编辑成员仅提新建议，移动端只读。历史读取不构成写入授权。

## Acceptance criteria

- [ ] Session API、界面及真实事务仓储贯通预览、明确开始、逐项保留、原请求核对、分批读取和最终重新确认；预览与刷新无写入或模型调用。
- [ ] 每个旧资产和失败范围有明确状态，无影响链接不等于默认保留；未完成项、失败、未知任务和新未决建议阻止确认。
- [ ] 锁定内容/依据完全相同才允许保留；改动被拒绝，原锁审计不改写，旧正式版本/内容不被覆盖。
- [ ] 旧活动基准、新正式上游及项目参数绑定处理身份；并发、期间上游变化、角色撤销、跨租户及伪造目标被拒绝。
- [ ] 候选、处理审计、活动/正式指针和针对新正式剧本的实际依赖原子保存，依赖失败完整回滚；重启和原请求重放不重复派生。
- [ ] 现有同上游审核/生成/恢复守卫不放宽，不伪造初次生成任务，不改原模型结果。
- [ ] 沿用已确认API、Worker、仓储、浏览器公共边界；本票无付费生成，完成类型/适用回归及独立Standards/Spec复核。
