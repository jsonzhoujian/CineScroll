# T07-02c — 待核对目标局部重生与未知结果恢复

**What to build:** 跨上游核对中，负责人/审核人明确选择未锁定待核对目标，使用当前正式上游局部重生，显式加载结果并继续审核；保留已完成/未选择项和旧正式版本，未知执行不重复付费。

**Blocked by:** T07-02b — 需要跨源有效/待核对依据划分、人工核对及明确解锁路径；经其依赖包含T07-02a。

**Status:** ready-for-agent（T07-02b 已完成）

## Accepted rules

- 任务固定旧基准、新正式上游、项目参数、选择范围、模型配置和原因；未明确选择或锁定目标不得生成。
- 仅合并所选成功项；失败保留原内容及处理状态，未处理目标不能变成有效资产或越过确认门禁。
- 原请求身份在发送前保存，刷新不自动POST；结果明确加载，不自动确认。
- 保存回执丢失读取原任务结果，模型未知且无结果时禁止原任务重跑、重提或同基准换请求绕过。

## Acceptance criteria

- [ ] API提交/原请求查询、Worker、真实事务仓储和浏览器打通待核对目标重生至重新审核/确认。
- [ ] 复用BYOK、许可、区域/模型/工作室准入、限流、独立扫描和受控传输；无公共run/recover接口。
- [ ] 模型边界前后及落库事务复验角色、锁、基准、上游、参数和目标；期间变化拒绝过期结果。
- [ ] 部分成功仅改变所选目标，错误身份/证据隔离；已完成、未选择和锁定内容/历史不被覆盖。
- [ ] 结果、处理状态、真实依赖和指针原子保存；保存回执丢失只读恢复，模型调用总数保持一次；无保存结果的未知执行不能重跑或换请求。
- [ ] 重启、跨租户、并发、浏览器刷新、存储失败零提交、显式加载/证据追溯与移动只读有公开边界回归。
- [ ] 类型检查、适用全量回归和独立Standards/Spec复核通过。

## Scope

只对明确授权目标生成；模型传输模拟，数据库用临时隔离PG/TLS。不部署、不启用生产、不调用真实付费模型、不自动提交。每次交付给出Git提交文案。
